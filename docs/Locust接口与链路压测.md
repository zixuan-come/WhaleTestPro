# Locust 接口与有序链路压测

2026-10-11。本次扩展的是 HTTP 压测能力，不是 JMeter 全功能或所有协议/插件兼容。

## 使用

压测监控 → 新建压测。先选择环境（导入 Host 与初始变量），再配置步骤：

- 单接口：手动输入，或从接口导入完整请求快照；支持 GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。
- 有序链路：添加/重排/删除步骤，或导入已保存的 HTTP 场景。保留场景的顺序、重复步骤、预期状态码、JSONPath 提取和 HTTP 业务断言。缺失用例/接口不会被跳过。
- 请求体：JSON、urlencoded 表单、原始文本（可手动指定 XML 等 Content-Type）、无请求体。Query 和 Headers 用 JSON 对象输入。
- 提取：`{"token":"$.data.token","order_id":"$.data.id"}`；后续 Headers 可填 `{"Authorization":"Bearer ${token}"}`，路径可填 `/orders/${order_id}`。JSON 中独立的 `${变量名}` 保留数字、布尔值、对象等原类型。
- 预期状态码为空时按 2xx/3xx 判断；可以指定 201/204 等。业务断言支持 json_eq/json_contains/json_gt/json_lt、header_eq/header_contains、response_time_lt（毫秒）、json_schema（只允许本地引用）。
- 默认失败结束本轮，不执行后续依赖步骤；下一轮从首步骤重新开始。可取消该选项继续执行独立步骤，但整轮仍记为失败。提取失败不提交部分变量。

创建只保存配置，点击运行才发流量。每个任务保存不可变的 JSON 快照，之后修改接口、环境或场景不会改变该任务。默认每轮结束等待 1 秒、单请求超时 30 秒，均可配置。

## 用户与轮次隔离

每个虚拟用户拥有自己的 Cookie 会话；每轮清空 Cookie、重建初始变量，上一轮的 Token/订单不会自动沿用。`${_vu_id}` 是虚拟用户 UUID，`${_iteration}` 是该用户当前轮次，可用于构造唯一业务标识。若需要每轮登录，请将登录作为第一个步骤。

数据集是对象数组，按每个用户的轮次循环并覆盖初始变量。不保证不同用户独占数据集账号；需要独占账号、随机数据、一次登录跨轮复用或更多控制器时，需单独扩展，不应假定与 JMeter 的 CSV/线程控制语义相同。

## 指标与安全边界

- HTTP RPS、失败率、P95/P99及按步骤统计来自实际 Locust 请求事件。统计名称固定为 step_01/step_02 等，详情映射回步骤名，避免订单 ID、Token、Query 值进入高基数标签。
- 整轮计数、失败轮次、平均整轮耗时和轮次吞吐单独采样，不作为伪 HTTP 请求加入 Aggregated。吞吐是完成轮次/采样经过时间，不是 HTTP RPS；不包含轮间等待的整轮耗时也不等于端到端用户周期。被停止中断的未完成轮次不计入完成轮次，已发送 HTTP 仍计入请求统计。
- 分布式 Worker 累计报告按 Worker 和租约合并，不重复相加，旧租约报告被忽略。停止时发送最后报告，但最后显示仍是控制面采样，不宣称消息不丢失/精确最终账本。
- Worker 在发送流量前从共享 Redis 读取并校验所属租约与快照；缺失、错误或过期配置拒绝执行，不回退为默认 GET。Master 在发 spawn 前广播租约，配置失败可以被控制面观察并使平台任务失败。
- 现有执行锁、控制凭证、停止/超时与清理逻辑继续生效。快照使用原有带 TTL 的目标键，所属任务清理时一并删除。旧任务 load_config 为 NULL，仍按原单 GET 执行。
- 错误统计只记录固定原因，不保存异常 URL、响应正文或提取值。配置快照本身可包含真实请求凭证，属于当前项目授权可读配置，尚未采用凭证保险库或静态加密；请使用测试账号，不把实际配置、原始证据或本地 SQL 备份上传 GitHub。

暂不支持 multipart 文件上传、WebSocket、gRPC、任意脚本、SQL setup/teardown、数据库断言、用例级数据集或自动重试。场景含这些配置时明确拒绝导入，不静默忽略。重定向默认关闭，开启可能访问其他 Host，须确认目标可信。导入后的旧 body 沿用 JSON，不自动猜测其他格式。

## 验证

后端离线回归与前端配置单元测试覆盖方法、请求体、变量类型、链路顺序、跨用户/轮次隔离、失败处理、配置限制与迁移兼容。前端通过生产构建。

`scripts/verify_locust_chain.py` 是显式启用的隔离验证：独立 Redis、真实 Locust Master/Worker、容器内 loopback Flask 模拟服务，2 用户，成功/业务失败各 3 秒；覆盖 7 种方法、3 种请求体、Token/订单传递、按步骤统计、停止及缺失配置拒绝流量。它不是 WhaleShop 性能基线，示例吞吐不能写入正式业务性能报告。验证脚本在 gevent 解释器退出时有两条 logging/greenlet finalization 提示；测试退出码为 0，不把提示隐藏为“无警告”。

`scripts/verify_perf_migration.py` 在一次性 MySQL 8 上验证两个数据库的 012 增量迁移、重复执行、旧行保留和 JSON 往返。迁移仅新增 load_config/iteration_stats 两个可空 JSON 列，没有清库或回填旧任务。

本地后端可运行 `python -m scripts.run_offline_tests`，前端可运行 `npm run test:perf` 和 `npm run build`。GitHub CI 后端使用合成配置并禁止外部业务 IO，增加前端测试及构建任务；本地配置和脚本不表示 GitHub Actions 已执行。真实 WhaleShop 压测、完整浏览器业务验收及正式性能报告另行进行。

## 实时结果（2026-10-18）

- 运行任务后自动打开“压测实时结果”；也可在运行中点击列表“实时结果”。无需停止任务或登录Grafana。
- Worker约每2秒将完整采样提交数据库，包含RPS、平均耗时、P95/P99、累计请求/失败数、接口维度统计、错误分布和历史趋势；页面每3秒轮询，同步更新已打开详情。
- 启动阶段允许零请求采样；结束时仍要求真实请求数大于0，不把空跑判为成功。采样按运行状态条件写入，停止后不复活任务。停止或故障保留已保存采样。
- 最近600个采样点用于曲线和采样明细，约20分钟；请求/失败计数和分位统计仍为本轮累计值。长任务不反复保存无限增长的JSON历史。
- 刷新失败提示并保留上次数据，后续重试；慢请求不重叠，切换项目清除旧详情、旧项目迟到响应不显示。
- “停止压测”会结束当前运行，不是可继续的暂停。平台展示聚合统计，不保存每条请求的完整响应正文。
