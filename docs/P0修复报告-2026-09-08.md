### 1. BUG-012：db_eq 断言 SQL 注入 ✅

**问题描述：**  
断言中的 `db_eq` 可以执行任意 SQL（DELETE/DROP/UPDATE 等），存在严重安全风险。

**修复方案：**  
在 `app/core/assertions.py` 中添加 SQL 校验：
- 只允许单条 SELECT 语句
- 拒绝多语句（`;` 分隔）
- 拒绝 DML/DDL（INSERT/UPDATE/DELETE/DROP 等）

**验证：**  
```python

    "SELECT value FROM items; DELETE FROM items",
])
def test_db_eq_rejects_write_or_multi_statement_sql(sql):
    # 验证恶意 SQL 被拒绝且数据未被修改
```

### 2. BUG-022：注册并发竞态导致 500 ✅

**问题描述：**  
高并发下两个请求同时通过"用户名不存在"检查后并发 INSERT，第二个触发唯一约束导致 `IntegrityError` 未捕获 → 500。

**修复方案：**  
在 `app/services/user.py` 中捕获 `IntegrityError`：
```python
except IntegrityError:
    db.rollback()
    raise HTTPException(status_code=400, detail="用户名已存在")
```

**验证：**  
```python

def test_register_maps_race_integrity_error_to_conflict(monkeypatch):
    # 模拟并发冲突，验证返回 400 而非 500
```

### 5. Docker 默认暴露端口安全加固 ✅

**问题描述：**  
Docker Compose 配置中多个服务暴露到宿主机所有网络接口，存在安全风险：
- RabbitMQ (5672/15672) 使用默认账号密码 guest/guest
- Prometheus (9090) 无认证暴露所有监控指标

**修复方案：**  
修改 `docker-compose.yml`：

1. **RabbitMQ 端口注释（第 34-37 行）**：
   ```yaml
   # P0 安全修复：RabbitMQ 端口仅限容器内访问，不暴露到宿主机
   # 如需本地调试管理界面，临时改为 "127.0.0.1:15672:15672"
   # ports:
   #   - "5672:5672"
   #   - "15672:15672"
   ```

2. **Prometheus 端口注释（第 94-96 行）**：
   ```yaml
   # P0 安全修复：Prometheus 仅限容器内访问，不暴露到宿主机
   # Grafana 通过内网访问 prometheus:9090，无需暴露端口
   # 如需本地调试，临时改为 "127.0.0.1:9090:9090"
   # ports:
   #   - "9090:9090"
   ```

**影响说明：**  
- ✅ RabbitMQ 和 Prometheus 仍可在容器内网正常工作
- ✅ Grafana 通过内网 `prometheus:9090` 正常访问数据源
- ✅ App/Worker 通过内网 `rabbitmq:5672` 正常通信
- ⚠️ 本地调试时如需访问，临时改为 `127.0.0.1:端口:端口` 限制仅本机访问

### 6. Grafana 匿名管理员权限 ✅

**问题描述：**  
Grafana 配置为匿名访问且角色为 Admin，任何人无需登录即可完全控制监控系统。

**修复方案：**  
修改 `docker-compose.yml` Grafana 环境变量（第 106-109 行）：
```yaml
environment:
  # P0 安全修复：禁用匿名访问，要求登录认证
  # 默认账号：admin / admin（首次登录会要求修改密码）
  GF_AUTH_ANONYMOUS_ENABLED: "false"
```

**影响说明：**  
- ✅ 访问 Grafana 需要登录（默认账号 admin/admin）
- ✅ 首次登录会强制修改默认密码
- ⚠️ 用户需要记录新密码
