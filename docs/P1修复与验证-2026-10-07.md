## 第二轮复查修复

1. **影子库身份混淆**：普通 `X-Shadow: 1` 请求返回 403；用户、团队、项目、调度等管理接口始终使用主库。内部示例订单回放使用独立用途的 30 秒签名凭证，绑定方法和路径，只允许 `/demo/orders`，不可复用用户 JWT。凭证只发送给本机内部回放地址（127.0.0.1/localhost:8000），且禁止跟随重定向转发凭证。外部环境只收到影子提示头，是否隔离写操作取决于被测系统，平台不保证。
2. **录制跨团队泄露**：取消默认项目 1 与原始请求头归属，使用授权依赖产生的项目上下文；公开 Mock 使用匹配规则的服务端 project_id；公开 demo 无鉴权项目上下文时不录制。团队等非项目接口不录制；历史误归属团队记录在列表、详情和回放中隐藏，不删除用户数据；部署前积压的此类消息也会丢弃。
3. **录制脱敏**：请求头、请求 Body 和响应 Body 在入队前递归脱敏，覆盖数组及嵌套对象；Worker 再次防御性脱敏，包含密码哈希、访问凭证和内部回放凭证。
4. **Locust 旧计时器停止新任务**：拦截 `/swarm` 的原生未跟踪计时器，替换为可取消的代次计时器。成功停止时取消旧计时器，过期回调检查代次；保留 Worker 退出后 Locust 自行到时停止的能力。测试使用实际 Locust Flask 路由及真实 gevent 定时器，但不启动 HTTP 服务或产生负载请求。
5. **带定时任务的项目无法删除**：删除顺序改为 Schedule 先于 Environment；回归明确填写 schedule.env_id 并启用 SQLite 外键检查。APITest 的非空项目删除也加入环境和定时任务。
6. **接口自动化缺口**：离线 fixture 不再自动注册或清理 Redis，加入禁止真实 HTTP/Docker 前置的守卫及独立 CI 门禁；补齐创建项目的 owner/admin/member/outsider 矩阵、定时任务环境校验/持久化/跨项目拒绝/启停保留套件，递归拒绝返回 hashed_password。压测用例等待 done 并验证 Celery ID、时间戳、真实请求计数与过程采样，CI 启动 Worker 和 Locust。

本轮没有清空数据库，也没有执行历史数据删除。历史合法项目录制记录未做批量重写；管理员仍可直接通过数据库审计被隐藏的错误归属记录。

## 配置变化

### SQL 连接边界

`TEST_DATABASE_URL` 未配置时，SQL setup/teardown 和 db_eq 不会访问任何平台表；普通 HTTP 执行不受影响。
需要 SQL 功能时，由数据库管理员创建独立测试库和独立账号，只授权该测试库的 SELECT、INSERT、UPDATE、DELETE。
禁止平台主库、影子库、root 账号、复用平台账号。MySQL 建立连接时会验证 SHOW GRANTS，
拒绝全局权限、跨库授权、角色继承、DDL 和 GRANT OPTION。不要把平台连接串复制到这里。
该账号不能拥有全局权限、其他库权限或 FILE／DDL／管理权限；独立账号不是仅改一个数据库名。
连接凭据放在本地 `.env` 或部署秘密配置中，不提交 Git。

### 定时任务

新建和更新必须传入当前项目的 env_id。环境 base_url 必须能从 Celery Worker 访问；
Compose 内测试本平台可使用 `http://app:8000`，不能使用宿主机映射端口假定 Worker 的 localhost 是后端。
新增 `011_schedule_environment` 幂等迁移，启动时对主库和影子库执行；手工 SQL 文件也提供。
既有任务不猜测目标环境。未选环境的启用任务会被移出 RedBeat 并提示编辑，补选后才能恢复执行。
被定时任务引用的环境不能直接删除，接口返回 409。

### 录制边界

录制仍是 best-effort，发布超时或容量满允许丢失录制记录，但有既有失败计数和日志。
`RECORDING_PUBLISH_TIMEOUT_SECONDS` 默认 1 秒。此次没有把录制升级为可靠消息 Outbox。

## 2026-10-10 提交前补充修复

上述“未 commit、未 push”是 10 月 7 日检查时的历史状态。本次按五批提交主项目；接口自动化仓库保持原样，其三批改动不在本次提交范围。

1. **压测启动/取消竞态**：旧 Worker 校验执行租约后、发布 ACTIVE 前，取消操作可能提前释放租约；新任务取得租约后，旧 Worker 仍发送 `/swarm`，覆盖新任务目标。取消改为分别比较并更新 queued/running：只有成功取消 queued 才直接释放执行租约；running 的清理由 Worker 或周期对账负责。新增 Redis 控制锁，串行化启动、停止及租约释放；启动前保留取消标记并重新校验运行状态，清理时在控制锁内重新检查 ACTIVE。
2. **录制失败日志泄露**：原来的 `exc_info=True` 会把校验异常中的原始请求内容写入日志。日志现在只保留请求方法、路径、异常类型及失败计数，不输出原始异常消息或堆栈。用真实日志格式化器覆盖消息队列异常与 Pydantic 校验异常的合成敏感输入。
3. **回归覆盖补充**：压测 Celery ID 不匹配、运行中删除拒绝、入队失败 503；定时任务环境/套件缺失和跨项目拒绝、被引用环境删除 409；RedBeat 参数及索引漂移、旧任务未选环境拒绝同步。

验证在 Git 暂存树导出的独立目录中执行：数据库使用内存 SQLite，Redis、消息队列及目标 HTTP 使用模拟依赖，禁止真实网络连接。并发竞态与日志泄露均先确认新测试在修复前失败，再确认修复后通过；前端使用已有依赖构建，不连接业务环境。
