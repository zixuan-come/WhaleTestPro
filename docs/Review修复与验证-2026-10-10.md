## 部署前配置

1. 在实际部署环境中配置独立且足够随机的 `LOCUST_CONTROL_TOKEN`，不要复用 JWT 的 SECRET_KEY，也不要提交真实凭证。
2. Compose 的 app、Worker 和 locust-master 必须使用同一控制凭证；相关容器需要重建/重建实例才能加载新代码与环境配置。K8s 使用对应 Secret。
3. 不要重新发布 8089，也不要通过额外代理暴露 Locust 控制端口；应用对用户的项目授权仍是入口，内部控制凭证不能替代项目授权。
4. API 项目 CI 已改为在 locust-master 内部执行带控制凭证的探测，不依赖宿主机公开 8089。本轮没有触发 CI。

- MySQL/InnoDB 并发：同时入队/删除压测任务；删除套件与汇总报告落库竞争。SQLite 回归不能证明真实行锁及跨进程行为完全一致。

- 安全边界：宿主机不能直连 8089；内部无凭证/错误凭证被拒绝，正确凭证可控制；凭证缺失时压测启动失败而不是旁路执行。
- 数据生命周期：执行过的套件可删除且历史报告仍可读；定时任务引用返回 409；执行中删除后仍生成汇总报告。
- 前后端交互：环境错误和显式 null 展示合理错误；前端不再出现 Locust 控制台直达入口。

## 已知边界

- 本轮脱敏保护新生成的录制和报告，不自动修复历史数据库中已保存的敏感证据。
- 脱敏依赖可识别字段和敏感提取来源；不承诺识别任意非结构化文本中的所有秘密。超大正文选择不采样，可能减少排障证据。
- 4–20 个字符并不保证所有多字节密码可接受，注册仍受 bcrypt 72 字节上限约束；没有静默截断。
- 本轮不需要新增数据库迁移：报告 suite_id 使用现有可空字段；没有清空真实数据或改动已有凭证。
- 终态压测任务的 Master 清理失败路径会保留记录/租约，但服务返回 None 被路由映射为 404，提示不够准确；Redis 不可用路径为 503。此项状态表述问题未在本次提交中扩展修复。
- 普通 run_case 的已知 context secret 别名证据及错误中的 URL 编码凭证不属于本轮新增链路脱敏保障，不声称已全面解决。
