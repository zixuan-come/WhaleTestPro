## 发现并修复的测试夹具问题

症状：压测核心测试的账号注册统一返回 422，导致 27 项用例无法进入测试正文。

根因：`CoreWorkspace.name("perf_core_")` 拼接 12 位随机后缀后为 22 字符，超过注册用户名的 20 字符上限。原离线压测契约使用预置身份，未走这个真实注册入口。

修复：仅把压测夹具前缀改为 `perf_c_`，保留随机后缀和平台注册规则。新增离线回归直接调用实际 `perf_owner` 夹具，检查注册和登录使用相同、合法长度的凭证；修复前稳定失败（22 > 20），修复后通过。之后重新执行 56 项真实集成用例，全部通过。

位置：`WhaleTestPro-APITest/testcases/test_perf_core/conftest.py`、`WhaleTestPro-APITest/tests/test_review_safety_contract.py`。

## 追加修复：Redis 不可用时鉴权返回 500

真实故障注入先完成登录、建团队和项目，然后仅停止临时 Redis。

- 期望：服务不可用时返回 503，继续拒绝放行，项目不删除。
- 实际：`DELETE /projects/{project_id}` 返回 500。
- 根因：`app/core/authentication.py` 的 `get_current_user` 先调用 `is_blacklisted(token)`；`app/core/blacklist.py` 的 Redis `exists` 抛出 `ConnectionError`。该异常未被转换成 503，请求未进入项目删除服务的租约检查。
- 数据证据：直接查询临时 MySQL，故障测试的项目和团队仍各有 1 行，删除没有执行；鉴权未被绕过。异常日志只包含类型、路由模板和栈位置，没有打印 token 或 Redis 凭证。
- 随后取得用户“修一下吧”的批准，追加修复并验证，不采用“Redis 故障时跳过黑名单”的处理方式。

修复限定于三个生产文件：`app/core/redis_client.py` 增加安全 Redis 操作边界，`app/core/blacklist.py`、`app/core/ratelimit.py` 包裹各自的读取/写入及限流操作。只捕获 `redis.RedisError`，转换为统一 503 和 `Retry-After: 5`，不返回驱动异常内容，不跳过安全检查，也不把黑名单写入失败当成注销成功。非 Redis 编程异常仍交给原错误处理；无效/已注销凭证的 401 和正常限流的 429 保持不变。

新增 `tests/test_auth_redis_outage.py`：修复前 12 failed、5 passed；修复后 17 passed（1.08 秒）。覆盖连接失败、超时、Redis 认证失败、黑名单读/写失败、限流计数/过期失败、安全操作前拒绝、异常信息不泄漏，以及正常注销按 JWT jti 隔离、401/429 和非 Redis 异常分类。

实际故障重跑使用新的独立 MySQL/Redis/RabbitMQ/后端，不启动 Worker 或 Locust，也不触碰原环境：

1. 合成账号正常登录、创建团队和项目，确认项目可访问。
2. 仅停止临时 Redis。项目 DELETE/GET、注销、登录均返回 503，响应含 `Retry-After: 5`；无效 JWT 仍返回 401。
3. 直接只读查询临时 MySQL，项目及团队仍各有 1 行，业务删除没有执行。
4. 恢复临时 Redis，原凭证重新访问项目为 200；注销成功后同一凭证再访问为 401。

最终检查输出：`real_redis_outage_and_recovery: passed`，`project_preserved: true`，`logout_revoked: true`。第一轮追加验证在 HTTP 503 检查通过后，因临时只读 SQL 使用了复数表名而中断；确认模型实际表名为 `project`/`team` 后完整重跑通过。临时脚本问题不计为产品修复失败，也没有跳过数据保留检查。注销读取成功后写入失败的时序用离线故障夹具确定性覆盖，未宣称真实 Docker 检查覆盖该时序。
