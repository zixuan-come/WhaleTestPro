# 压测发布补偿与代理地址刷新

二审后先在包含前轮 18 项修复的工作区重新复现，再修复以下两项。本文记录提交前的验证结果，不代表已完成云端部署。

## 压测入队失败补偿

旧执行入队时发生晚到的 Broker 异常，可能已被用户停止并重新开始。原实现只根据任务 ID 将当前 queued/running 标记失败，甚至停止新一轮 Locust。

修复后，路由把原 Celery 执行 ID 传给补偿服务，仓储更新同时要求项目、任务、活动状态和执行 ID 匹配。清理 Locust 时使用请求开始时的原执行 ID，不依赖提交后可能已经重新加载为新执行的 ORM 对象。缺少执行 ID 时明确拒绝补偿，不能退回仅按任务 ID 操作。

回归覆盖：路由传递原 ID；旧发布失败不修改或停止新执行；当前 queued/running 发布失败正常结束；提交后读取已变为新一轮记录时也不误清理；缺少 ID 被拒绝。

## Nginx 后端地址变化

原配置在启动时解析 `app:8000`。仅重建后端且 IP 变化时，服务 DNS 直连已经正常，前端仍使用旧 IP 返回 502，直到 reload。

选择 Docker DNS `resolver 127.0.0.11 valid=5s` 和不含 URI 的变量 `proxy_pass`。三个 API location 先移除 `/api` 前缀，再转发完整的新 URI 与原 query。没有使用需要特定新版 Nginx 的 `upstream resolve` 语法，也不依赖部署脚本强制重启前端。执行接口的 660 秒读取超时保留，内部上游连接超时为 5 秒。非 Docker 部署需替换 DNS 与后端地址。

真实集成测试使用 Nginx 1.31.2、两个临时基础 Python HTTP 服务和独立内部网络，不发布端口，不访问或挂载业务数据。替换前后共验证 22 次请求，涵盖普通 API、精确匹配的回归执行路径和全部长请求正则路径，检查 GET/POST、请求体、重复 query 和百分号编码。后端 IP 改变后不 reload、不重建前端即恢复，代理容器 ID 保持一致。临时容器和网络在 finally 中清理。

普通离线入口包含发布补偿用例，Nginx 集成默认跳过。专用隔离环境可显式执行：

```bash
WHALE_NGINX_DNS_INTEGRATION=1 python -m pytest tests/test_nginx_upstream_dns.py -q
```

该命令需要 Docker CLI/daemon 和 `python:3.10-slim`、`nginx:alpine` 镜像，创建带随机名称的临时内部网络与容器，不涉及已有应用容器。可用 `WHALE_NGINX_DNS_RESULT_PATH` 指定保存转发验证结果的文件。
