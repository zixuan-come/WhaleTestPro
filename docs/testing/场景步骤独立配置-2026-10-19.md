# 场景步骤独立配置（2026-10-19）

从用例库添加时，复制当时的有效 HTTP 请求、期望状态、断言、提取规则及来源信息。每个步骤使用独立标识，同一来源可以出现多次并分别配置；模板后续编辑或删除不影响已保存副本。重新应用模板需要用户主动确认，只更新当前步骤。

## 使用与契约

- 页面采用两栏：左侧搜索/选择场景，右侧展示步骤。点击“从用例库添加步骤”打开弹窗，支持搜索、接口筛选、20 条分页、跨页保留选择及按勾选顺序批量添加；原用例仍可再次添加。
- 点步骤行的“编辑”或双击步骤，修改名称、方法、路径、Path/Query/Headers/Body、期望状态及高级配置，点“应用到当前步骤”，最后保存场景。行内直接显示方法/路径和期望状态，拖拽手柄支持上下方向键调整顺序。
- “重新应用模板”位于步骤编辑窗口，载入后先形成草稿；应用才更新步骤，关闭或取消仍保留原配置。读取失败也保留正在编辑的草稿。场景删除位于顶部“更多”菜单。
- 高级配置默认收起。未改变的请求字段保留原 JSON 类型；取消编辑不改变步骤。运行未保存场景时，确认后先保存再执行，保存失败不运行旧版本。
- `POST/PUT /scenarios` 新增有序 `steps`；列表和详情返回相同快照。`case_ids` 为来源投影，兼容旧客户端；两者同时提交须一致。旧客户端重排时保留已有独立配置，新增引用才读取模板。
- 步骤校验当前项目来源和接口；已授权保存的来源失效后可继续使用副本。初次添加就已缺失的旧引用保留为失效步骤。不能通过伪造失效状态或跨项目 ID 获取其他项目配置。
- 场景执行、套件、定时回归和报告使用保存后的快照。套件只对实际配置等价的独立用例去重，已修改步骤不会因来源 ID 相同而跳过独立用例。预览与运行采用同一规则。
- 压测场景导入保留步骤名称、重复项、状态码、断言、提取、请求参数及 Path 变量。依旧拒绝 SQL、用例数据集、自动重试和不支持的断言，不静默丢弃。场景链路仍不执行这些非 HTTP 来源配置。

## 数据库与部署

`021_scenario_step_snapshots` 为 scenario 增加 steps JSON，为历史场景报告步骤增加可空 step_id。原有 case_ids、资产和报告不删除。两个数据库按当前同项目用例及有效接口配置回填，保留顺序、重复及显式 null；缺失引用明确标记。已有步骤不重复复制或刷新。

升级前备份两个数据库并停止 app/worker/beat 写入，使用新镜像运行 `python -m scripts.run_migrations`，再启动全部新服务。超过 1000 步、2 MiB 或旧配置无效时中止，不截断、不删数据。主库和影子库均需要升级。
