# 报告目录与清理（2026-10-20）

用户确认在“测试报告”内增加单层自定义目录和报告删除功能。目录在项目内共享，保留原来的执行类型分类，并增加“全部”标签；报告只能由执行生成。

## 页面行为

- 左侧为“全部报告”“未归档”和自定义目录，支持收起；新建目录可使用“2026-10-20-测试者名称”等名称。
- 目录支持新建、重命名、删除；删除目录会保留报告并返回“未归档”。新旧报告都可以归档，报告不重复出现在多个目录。
- 支持单条操作、本页勾选和跨页勾选，最多一次 500 份。切换目录、类型或筛选会清空选择。
- 单条和批量删除使用站内确认弹窗；运行中的报告不能删除。错误保留选择并提示原因，成功刷新统计与列表。
- 所有者与管理员可管理报告；普通成员需在团队权限中开启“测试报告”。只读用户看不到管理按钮，服务端也会拒绝写入。

## HTTP 契约

沿用现有身份认证和 `X-Project-Id` 项目上下文，响应使用 `ApiResponse`。以下新增 7 项方法与路由组合，全平台由 109 项增至 116 项。

| 方法 | 路由 | 作用 |
| --- | --- | --- |
| GET | `/reports/folders` | 返回目录、每目录数量、全部/未归档数量以及 `can_manage` |
| POST | `/reports/folders` | 创建目录，成功 201 |
| PUT | `/reports/folders/{folder_id}` | 重命名目录 |
| DELETE | `/reports/folders/{folder_id}` | 删除目录，保留报告 |
| POST | `/reports/executions/move` | 单条/批量移动或移出目录 |
| POST | `/reports/executions/delete` | 批量删除根报告及明确归属的执行证据 |
| DELETE | `/reports/executions/{report_id}` | 删除一份根报告及其执行证据 |

目录名称请求为 `{"name":"2026-10-20-张三"}`，去除首尾空白后 1～100 字符。同项目名称经 NFKC 与 casefold 规范化后唯一，冲突返回 409。普通成员管理操作要求 `report.write`，未授权返回 403。

移动请求示例：

```json
{"report_ids":["run-12","legacy-7","scenario-8"],"folder_id":3}
```

`folder_id: null` 表示移回未归档。删除请求仅含 `report_ids` 数组；两者均为 1～500 个引用，重复引用去重，禁止附加未定义字段。报告引用沿用 `run-N`、`legacy-N`、`scenario-N` 字符串，不能只传整数。

`GET /reports/executions` 增加 `kind=all` 和 `folder_id`：不传目录表示全部目录，`0` 表示未归档，正整数表示该项目的指定目录。为兼容旧客户端，不传 `kind` 时仍默认 `case`。搜索、状态、日期和统计均在服务端分页前结合目录筛选；目录侧边数量始终基于当前项目所有根报告。

## 删除与项目隔离

只允许独立根报告作为管理入口。删除现代报告时，按显式父 ID 递归清理同项目子执行、关联的旧用例/场景报告及场景步骤；删除历史场景报告时清理它自己的步骤。不推测历史记录之间的关系。

接口、用例、场景、套件等配置保留。整批操作处于一个数据库事务内：任一报告不存在、已删除、跨项目或不是根报告，返回 404 并回滚；任一现代根/子执行 `passed` 未定或状态为 running/pending/queued，删除返回 409 并回滚。页面切换项目时忽略旧请求，关闭相关弹窗，避免误操作旧选择。

## 数据迁移与本地验证

新增 `report_folder`、`report_folder_item` 两张表，迁移标记为 `022_report_folders`，主库和影子库分别执行，支持重复启动。已有报告表不回填、不清空；没有目录归属记录的报告自然进入未归档。删除项目时一并清理新增目录及归属，避免阻塞原有项目删除。

- 后端完整 `tests` 测试目录：645 通过、10 跳过；包括权限、跨项目、旧报告、递归清理、整批回滚、迁移幂等及项目删除。
