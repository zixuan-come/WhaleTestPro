# 标签功能移除（2026-10-19）

用例分组统一由场景、测试套件和明确选择的用例清单管理。保留名称搜索、所属接口搜索/筛选、跨页选择、顺序调整及场景与独立用例去重，不再通过标签筛选或动态扩大执行范围。

## 变更

- 用例新建、编辑、列表和 API 输出移除 `tags`；高级配置默认收起，保留已配置项数量和校验失败时自动展开。
- 套件移除标签输入、筛选、自动加入和执行分支，只执行明确保存的场景/用例。
- 回归候选列表移除标签筛选和展示。预览与执行继续使用同一份明确选择，接口数量仍为 107。
- 定时调度派发只携带 `project_id` 和 `schedule_id`。Worker 读取当前数据库定义，无明确选择或绑定套件时拒绝执行；停用、删除和跨项目保护保留。
- 用例/套件请求包含旧 `tags`，或定时任务请求包含旧 `tag` 时返回 422，避免静默忽略后改变执行范围。Swagger 路由分组的 `tags` 和 HTTP 方法徽标不属于已移除的业务功能。

## 数据库与部署

迁移 `020_remove_case_tags` 在主库和影子库删除 `test_case.tags`、`test_suite.tags`、`schedule.tag`，可重复执行，不删除用例、接口、场景或报告。

即使用户没有旧套件或任务，升级仍需备份两个数据库。若存在旧规则，迁移先将同项目当前匹配用例追加到明确清单，保持原顺序并去重；旧全量任务固定为当前项目用例快照。超过套件 100 项或定时选择 1000 项时中止，不能截断。无匹配用例的旧定时规则停用，不回退为全量执行。新增用例以后不会自动加入。

本次包含后端和数据库变更，不能沿用“只更新 frontend”的部署方式。备份后构建镜像，停止 app/worker/beat，运行 `python -m scripts.run_migrations`，再更新服务。服务器更新由用户执行，发布前先提交推送主仓；本记录不表示云端已更新。
