# BUG-021 账号规则产品决策建议

## 决策问题
账号 trim 规则和字符集规则未定义，需要明确产品规则。

## 推荐方案：严格规则（方案 1）

### 规则定义
1. **自动 trim**：注册和登录时自动去除首尾空格
2. **字符集限制**：
   - 仅允许：英文字母（a-z, A-Z）、数字（0-9）、下划线（_）、连字符（-）
   - 正则：`^[a-zA-Z0-9][a-zA-Z0-9_-]{3,19}$`
3. **长度限制**：4-20 个字符
4. **其他约束**：
   - 必须以字母或数字开头
   - 不允许纯数字
   - 大小写不敏感（登录时统一转小写比对）

### 理由
- ✅ 安全：避免注入、编码问题、同形字攻击
- ✅ 兼容：符合主流平台习惯（GitHub、GitLab、Docker Hub）
- ✅ 易用：方便 URL 传参、日志记录、API 调用
- ✅ 清晰：用户一看就懂，减少困惑

### 实现影响
**后端修改：**
- `app/schemas/user.py` - 添加 username 校验器
- `app/services/user.py` - 注册和登录时 trim + 转小写

**前端修改：**
- `frontend/src/views/Login.vue` - 添加实时校验提示
- 提示文案："用户名只能包含字母、数字、下划线和连字符，4-20个字符"

**数据迁移：**
- 检查现有用户表是否有不符合规则的账号
- 如果有，通知用户修改或系统自动标记

### 替代方案对比

| 方案 | 支持中文 | 安全性 | 复杂度 | 推荐度 |
|------|---------|--------|--------|--------|
| 方案1：严格规则 | ❌ | ⭐⭐⭐⭐⭐ | 低 | ⭐⭐⭐⭐⭐ |
| 方案2：宽松规则 | ✅ | ⭐⭐⭐ | 中 | ⭐⭐⭐ |
| 方案3：不限制 | ✅ | ⭐ | 低 | ⭐ |

### 示例代码

```python
# app/schemas/user.py
import re
from pydantic import field_validator

class UserRegister(BaseModel):
    username: str
    password: str

    @field_validator("username")
    @classmethod
    def validate_username(cls, value: str) -> str:
        # 自动 trim
        value = value.strip()

        # 长度检查
        if len(value) < 4 or len(value) > 20:
            raise ValueError("用户名长度必须在 4-20 个字符之间")

        # 字符集检查
        if not re.match(r"^[a-zA-Z0-9][a-zA-Z0-9_-]{3,19}$", value):
            raise ValueError("用户名只能包含字母、数字、下划线和连字符，且必须以字母或数字开头")

        # 转小写（大小写不敏感）
        return value.lower()
```

## 决策建议
**推荐采用方案 1（严格规则）**，原因：
1. 这是一个测试平台，主要面向技术团队，英文用户名足够
2. 严格规则能避免大量潜在问题
3. 实现简单，无需处理复杂的 Unicode 情况
4. 符合业界最佳实践

如果未来确实需要支持中文用户名，可以后期演进到方案 2。
