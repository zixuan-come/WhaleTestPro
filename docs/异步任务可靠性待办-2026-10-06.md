# 异步任务可靠性待办

> 建立时间：2026-10-06
> 范围：Celery、RabbitMQ、压测任务、流量录制、定时任务及其可观测性。

## 本批已实现，等待 Docker 人工验收

- [x] **压测任务不再过早进入 `running`**：API 入队阶段使用 `queued`，Celery Worker 真正取得任务后才原子切换为 `running`。
- [x] **Worker 异常退出后的僵尸任务回收**：任务保存 `queued_at`、`started_at`、`heartbeat_at`、`finished_at` 和 `failure_reason`；运行期间刷新心跳，API 查询和 30 秒周期任务都会回收超时任务。
- [x] **RabbitMQ 队列积压监控**：启用 `rabbitmq_prometheus`，Prometheus 抓取 `rabbitmq:15692`；增加待消费积压、无消费者和未确认消息告警，并新增 Grafana RabbitMQ 队列看板。
- [x] **修正 Worker Prometheus 抓取目标**：由错误的 `host.docker.internal:8002` 改为 Compose 内部地址 `worker:8002`。
- [x] **关联 Celery Task ID 与业务任务 ID**：发送任务前生成 Celery ID，保存到 `perf_tasks.celery_task_id`，并把同一 ID 交给 Celery。

对应数据库升级为 `010_perf_task_lifecycle`，同时覆盖主库和影子库，支持重复执行。

## 后续代码待办

- [ ] **异步能力独立就绪检查**：增加 `/health/async-ready` 或缓存式 Worker 心跳检测；不要在高频基础探针中直接调用耗时的 `celery inspect ping`。
- [ ] **流量录制消费失败重试**：对瞬时数据库错误做有限次数、指数退避重试，并增加 Worker 消费失败指标；如要求不丢数据，再升级为 Outbox。
- [ ] **Celery 超时与丢失任务策略**：按任务设置软/硬超时、有限重试、结果过期；完成幂等保护后再启用 `acks_late` 和 `reject_on_worker_lost`。
- [ ] **异步任务幂等性**：为压测、定时执行、报告和流量录制建立唯一运行/事件 ID，防止消息重投造成重复执行或重复报告。
- [ ] **按业务拆分队列**：将 `perf`、`traffic`、`schedule` 分配到独立队列和 Worker，避免长压测阻塞短任务。
- [ ] **Outbox 可观测性**：监控待处理数量、最老事件年龄、重试次数和最近失败原因，并在管理端提供查询入口。
- [x] **README 异步边界校正**：2026-10-10 已明确手动测试套件当前同步执行；定时套件/回归、性能测试和流量录制才经过 Celery。
- [ ] **手动测试套件异步化（可选）**：改为 `202 + run_id`，增加执行状态查询和报告关联；当前需求不把它列入版本验收。
