## 1. 本轮已完成

### 1.1 统一权限模型

- 新增 `ProjectContext`，一次性解析当前用户、项目、团队身份、兼容身份和已启用的模块权限。
- 新增 `Resource`、`Action` 枚举，权限动作统一为 `read`、`write`、`execute`、`manage`、`owner`。
- 新增 `resolve_project_context()`、`is_allowed()`、`authorize()`、`require_project()` 和路径参数版本的项目上下文依赖。
- 身份认证逻辑从原 `deps.py` 拆分到 `authentication.py`，项目授权逻辑集中到 `authorization.py`。
- 删除根据 HTTP 方法、URL 路径或 `/run` 后缀猜测权限的运行时代码。

### 1.2 统一权限来源

- 团队项目只以 `TeamMember` 作为访问和角色判断来源。
- `ProjectMember` 暂时保留为历史兼容投影，用于兼容旧数据和原项目成员 API。
- 团队项目中，即使旧 `ProjectMember` 记录为 `owner`，也不能抬高 `TeamMember` 的实际权限。
- 没有团队归属的历史项目仍允许通过 `ProjectMember` 访问，避免旧数据立即失效。
- 团队成员增删、角色变化、项目迁移时同步维护 `ProjectMember` 兼容投影。

### 1.3 显式路由授权

接口、用例、环境、Mock、调度、压测、场景、套件、报告、回归、流量录制/回放和项目管理路由均已改为显式声明资源与动作。

当前角色规则如下：

| 角色 | read | write | execute | manage | owner |
|---|---:|---:|---:|---:|---:|
| Owner | 是 | 是 | 是 | 是 | 是 |
| Admin | 是 | 是 | 是 | 是 | 否 |
| Member | 是 | 按模块开关 | 是 | 否 | 否 |

说明：

- 普通成员默认可以读取和执行，但默认不能修改资源。
- 普通成员的写权限按模块配置：`interface.write`、`case.write`、`environment.write`、`mock.write`、`schedule.write`、`perf.write`、`scenario.write`、`suite.write`。
- 项目成员管理使用 `manage`，项目删除和迁移使用 `owner`，不与普通资源编辑混用。
- `/mock/{project_id}/...` 仍是供外部被测系统调用的公共挡板入口；`demo_order` 仍是公共演示接口，不进入项目权限域。

### 1.4 权限配置界面与测试

- 团队管理页已增加“普通成员写权限”配置区，八个模块均可单独开启或关闭，包含此前缺失的 `suite.write`。
- 新增授权策略单元测试，覆盖 Owner/Admin/Member 矩阵、模块权限隔离、旧成员记录不得提权、团队成员无兼容投影时仍可访问、历史无团队项目兼容和拒绝访问返回 403。
- 更新团队管理测试，覆盖项目迁移后的成员投影清理和 `suite.write` 权限键。

## 2. 还需要写代码的工作

以下项目不属于本轮权限核心实现，但在最终交付前仍建议完成。当前缺陷总账没有未处理的 P0/P1 功能缺陷，下面主要是测试补强、部署可靠性和技术债。

### P1：最终验收前应完成

1. **补齐并运行 HTTP 黑盒权限矩阵**  
   在 `WhaleTestPro-APITest` 中补充 Owner、Admin、Member、未入组用户、跨项目访问、八个模块写权限、执行权限、成员管理、项目删除/迁移以及公共 Mock 入口用例。黑盒测试只能通过 HTTP 调平台，不能导入平台业务代码。历史结果 `212 passed, 1 skipped` 早于近期改动，不能作为当前结论。

2. **把数据库迁移改为可重复执行的正式迁移**  
   `migrations/001_add_test_suite.sql` 中多个 `ALTER TABLE ADD COLUMN/CONSTRAINT/INDEX` 不是完全幂等。需要通过信息架构判断或正式迁移工具处理，并保证主库、影子库都执行同一版本。`Base.metadata.create_all()` 不会给已有表补字段。

3. **隔离并发压测的 Locust 目标路径**  
   `app/services/perf.py` 仍写入全局 Redis 键 `locust:target_path`。两个压测任务并发时可能互相覆盖目标路径，应改为任务级键，或把目标路径直接随启动参数传给独立任务。

### P2：一致性和产品口径

4. **统一测试套件 API 响应封装**  
   套件路由目前直接返回 `SuiteOut`/列表，而多数业务接口使用 `ApiResponse`。若统一，需要同时调整前端 API 解包方式和黑盒用例，避免只改后端造成兼容问题。

5. **确认密码长度后再决定是否改代码**  
   当前实现和近期规则偏向 `8–20` 位，早期沟通出现过 `4–20` 位。此项先由产品确认；只有口径改变时，才需要同步修改后端 Schema、前端校验、提示文案和测试。
