# 认证与会话

> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

## 1. 文档信息
| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |
| 目标用户 | 访客、已登录用户 |
| 关联模块 | 用户、JWT、安全依赖、前端路由 |

## 2. 背景与目标
认证模块建立可识别、可撤销的用户会话，保护项目和测试资产，并降低账号枚举与暴力登录风险。

## 3. 范围
### 本期范围
注册、密码登录、JWT 校验、当前 Token 登出、IP 登录限流、前端登录态路由。
### 非本期范围
找回密码、修改密码、验证码、多因素认证、第三方登录和单点登录。

## 4. 角色与权限
项目访客可注册和登录；已登录用户可登出当前 Token 并访问受保护资源。

## 6. 功能需求
### AUTH-F01 用户注册
- 用户故事：作为访客，我希望用用户名和密码注册账号。
- 前置条件：字段存在、类型正确、用户名非空。
- 主流程：提交 -> 校验唯一性 -> 哈希密码 -> 创建用户 -> 返回用户摘要。
- 业务规则：用户名全局唯一；数据库不保存明文密码。
- 验收标准：合法请求 201；重复用户名 400 且不产生重复数据；非法字段 422。

### AUTH-F02 用户登录
- 用户故事：作为用户，我希望登录并获得 Bearer Token。
- 主流程：查用户 -> 校验密码 -> 生成 JWT -> 返回 access_token。
- 业务规则：错误凭证统一返回 401 文案；JWT 包含用户标识、exp、jti。
- 验收标准：正确凭证 200；错误凭证 401 且不泄露账号是否存在。

### AUTH-F03 登录频率限制
- 用户故事：作为维护者，我希望限制单 IP 登录尝试。
- 业务规则：60 秒最多 5 次，第 6 次返回 429；窗口过期后恢复。
- 验收标准：超限请求不进入正常登录处理。

### AUTH-F04 JWT 会话校验
- 用户故事：作为受保护接口，我希望只接受有效会话。
- 主流程：读取 Authorization -> 校验格式、签名、exp、jti 黑名单和用户存在性。
- 验收标准：任一校验失败返回 401；有效 Token 可访问业务接口。

### AUTH-F05 当前 Token 登出
- 用户故事：作为用户，我希望只撤销当前设备会话。
- 业务规则：仅拉黑当前 jti，TTL 等于剩余有效期；其他 Token 不受影响。
- 验收标准：成功 200 且 data=null；当前 Token 后续 401，其他 Token 仍可用。

### AUTH-F06 前端登录态路由
- 用户故事：作为用户，我希望页面根据登录状态自动跳转。
- 业务规则：已登录访问登录页跳转接口页；未登录访问业务页跳转登录页；提交中禁用按钮。
- 验收标准：刷新和 Token 失效后的跳转行为一致。

## 7. 非功能要求
密码使用安全哈希；认证失败不泄露账号存在性；Redis 不可用时记录可诊断错误。

## 8. 当前实现与待确认项
已实现：JWT、Redis jti 黑名单、IP 限流、前端登录态守卫。
待确认：密码复杂度、用户名字符集、多设备会话和全部会话注销。
