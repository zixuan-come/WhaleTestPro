## 2. 背景与目标
项目是平台的数据隔离根，并归属于团队。用户在选中的团队和项目上下文中管理环境、接口、用例、套件、场景、报告、Mock、回归、调度、性能和流量资产；团队角色与普通成员写权限共同决定项目操作权限。

## 3. 范围
本期包含项目 CRUD、按团队筛选和选择、项目成员兼容接口、资源隔离、团队归属及跨团队迁移。团队创建、邀请、成员管理、所有权转让和权限配置见《14-团队协作与权限》。不包含组织/部门、项目归档恢复和审计日志。

## 6. 功能需求
### PRJ-F01 创建项目
- 用户故事：作为已登录用户，我希望创建独立项目；作为团队 owner/admin，我希望将项目直接创建在团队内。
- 前置条件：名称非空且不超过 100 字符，描述可空且不超过 500 字符；指定 team_id 时当前用户须为该团队 owner/admin。
- 主流程：填写 -> 校验团队权限与全局名称唯一 -> 创建项目；未指定团队时创建者成为 ProjectMember owner，指定团队时同步团队成员的 ProjectMember 兼容投影 -> 返回 201。
- 验收标准：重名 409；团队 member 在团队内创建时 403；团队不存在或不可访问 404；未登录 401；字段非法 422；成功后对应项目列表可见。

### PRJ-F02 查看与选择项目
- 用户故事：作为团队成员，我希望选择所属团队下的项目并设置后续请求上下文。
- 主流程：按当前用户或 team_id 返回可访问项目 -> 选择 -> 保存项目 ID -> 请求发送 X-Project-Id；未绑定团队的兼容项目按 ProjectMember 判断访问。
- 规则：无选择时自动选择可用项目；无项目进入项目管理页。
- 验收标准：非成员详情 404；删除当前项目后前端清空旧 ID。

### PRJ-F03 编辑项目
- 用户故事：作为团队 owner/admin 或兼容项目 owner，我希望修改项目名称和描述。
- 规则：需要 project.write；团队 member 无项目级写权限配置项，不能编辑项目；未绑定团队项目按 ProjectMember 兼容授权；名称仍需全局唯一和长度校验；团队归属变更统一使用迁移接口。
- 验收标准：owner/admin 合法更新成功；member 403；重名 409 且数据不变。

### PRJ-F04 删除项目
- 用户故事：作为 owner，我希望删除不再使用的项目。
- 规则：成员和关联资产删除需事务一致，失败整体回滚；成功 data=null。
- 验收标准：删除后详情 404、资产不可访问；非 owner 403；当前选择清空。

### PRJ-F05 查看项目成员
- 用户故事：作为团队成员，我希望查看项目的成员兼容投影和角色。
- 规则：只返回本项目；团队项目的角色投影应与 TeamMember 一致，不作为独立授权依据。
- 验收标准：团队成员可查；非成员 404；成员数据不串项目；团队角色变更后投影同步。

### PRJ-F06 搜索并添加成员
- 用户故事：作为 owner/admin，我希望通过兼容接口维护项目成员。
- 前置条件：关键词 2 至 50 字符，目标用户未加入。
- 主流程：搜索候选（最多 50 条） -> 选择 admin/member -> 创建关系。
- 规则：不可通过项目成员接口绕过 TeamMember 提升权限；团队项目新增成员应优先使用团队邀请流程；不可添加 owner；重复添加 409；用户不存在 404。
- 验收标准：member 403；非法角色 422；成功后成员列表出现；团队项目中仅新增 ProjectMember 不能让非 TeamMember 获得访问权。

### PRJ-F07 修改成员角色
- 用户故事：作为 owner/admin，我希望通过兼容接口在 admin/member 间调整职责。
- 规则：owner 不可降级；member 无权；目标成员须属于当前项目；团队项目最终权限仍以 TeamMember 为准，ProjectMember 角色不能抬权。
- 验收标准：合法更新成功；owner 目标 409；跨项目成员 404；团队项目中 ProjectMember 角色变化不改变 TeamMember 决定的实际权限。

### PRJ-F08 移除成员
- 用户故事：作为 owner/admin，我希望回收普通成员访问权。
- 规则：owner 不可移除；团队项目应通过团队成员管理回收访问权；仅移除兼容投影不得导致 TeamMember 丧失或获得额外权限。
- 验收标准：member 403；owner 目标 409；成功后兼容关系删除；团队项目中仍存在 TeamMember 时实际访问权不受该删除影响。

### PRJ-F09 项目资源隔离
- 用户故事：作为用户，我希望项目资产严格隔离。
- 前置条件：项目请求携带 Token 和 X-Project-Id。
- 主流程：认证 -> 建立 ProjectContext -> 按 Resource/Action 校验权限 -> Repository 按 project_id 查询/变更。
- 规则：不能仅凭资源 ID 跨项目访问；无权优先 404。
- 验收标准：A 用户访问 B 资源 404/权限错误；缺项目头 422；缺 Token 401。

### PRJ-F10 项目与团队绑定
- 用户故事：作为团队管理者，我希望项目明确归属于一个团队并继承团队成员关系。
- 主流程：创建项目时提交 team_id -> 校验团队管理权限 -> 保存归属 -> 为团队成员同步兼容投影。
- 规则：team_id 仅能指向当前用户可管理的团队；项目列表支持按 team_id 筛选；同一项目同一时刻只归属一个团队。
- 验收标准：owner/admin 可在本团队创建；member 创建被拒绝；绑定后团队成员按统一权限访问；跨团队数据不串联。

### PRJ-F11 项目跨团队迁移
- 用户故事：作为项目 owner，我希望将项目迁移到自己拥有的另一团队。
- 前置条件：操作者具备源项目 owner 权限，且是目标团队 owner。
- 主流程：提交目标 team_id -> 校验源项目和目标团队权限 -> 更新归属 -> 删除旧投影并按目标团队成员重建投影。
- 规则：迁移必须使用专用接口；目标团队不存在或不可访问时不改变数据；操作事务失败整体回滚。
- 验收标准：迁移成功后旧团队成员失去访问，目标团队成员获得对应访问；源项目 admin/member 或仅为目标团队 admin 均 403；失败时项目归属和投影保持原状。

## 7. 非功能要求
后端强制鉴权；跨项目错误不泄露存在性；成员投影同步和迁移操作保持事务一致；删除事务可回滚；错误码稳定可断言。

## 8. 当前实现与待确认项
已实现：全局项目名唯一、团队归属、按团队筛选、统一 ProjectContext/Resource/Action 鉴权、X-Project-Id 隔离、TeamMember 主授权、ProjectMember 兼容投影和项目跨团队迁移。
当前限制：旧项目成员接口为兼容能力，不应作为团队项目的权限配置入口。
待确认：项目删除恢复、报告/流量/性能结果保留期限。
