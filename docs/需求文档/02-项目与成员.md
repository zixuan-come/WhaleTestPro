## 2. 背景与目标
项目是平台的数据隔离根，并归属于团队。用户在选中的团队和项目上下文中管理环境、接口、用例、套件、场景、报告、Mock、回归、调度、性能和流量资产；团队角色与普通成员写权限共同决定项目操作权限。

## 3. 范围
本期包含项目 CRUD、按团队筛选和选择、资源隔离、团队归属及跨团队迁移。团队创建、邀请、成员管理、所有权转让和权限配置见《14-团队协作与权限》。不包含组织/部门、项目归档恢复和审计日志。

| 编辑项目 | 允许 | 允许 | 禁止 |
| 删除项目 | 允许 | 禁止 | 禁止 |

约束：项目必须归属团队，TeamMember 是唯一成员与权限来源。owner 唯一性、角色调整和成员退出规则以团队成员关系为准。

## 6. 功能需求
### PRJ-F01 创建项目
- 用户故事：作为团队 owner/admin，我希望在自己管理的团队中创建项目。
- 前置条件：用户已创建或加入团队并选择当前团队；名称非空且不超过 100 字符，描述可空且不超过 500 字符；`team_id` 必填，当前用户须为该团队 owner/admin。
- 主流程：选择团队 -> 填写项目 -> 校验团队权限与全局名称唯一 -> 创建项目 -> 返回 201。
- 验收标准：未选择团队时前端提示先创建或加入团队；缺少 `team_id` 或字段非法返回 422；重名 409；团队 member 创建时 403；团队不存在或不可管理时 403；未登录 401；成功后对应项目列表可见。

### PRJ-F02 查看与选择项目
- 用户故事：作为团队成员，我希望选择所属团队下的项目并设置后续请求上下文。
- 主流程：依据当前用户的 TeamMember 关系，按全部团队或指定 team_id 返回可访问项目 -> 选择 -> 保存项目 ID -> 请求发送 X-Project-Id。
- 规则：无选择时自动选择可用项目；无项目进入项目管理页。
- 验收标准：非成员详情 404；删除当前项目后前端清空旧 ID。

### PRJ-F03 编辑项目
- 用户故事：作为团队 owner/admin，我希望修改项目名称和描述。
- 规则：需要 project.write；团队 member 无项目级写权限配置项，不能编辑项目；名称仍需全局唯一和长度校验；团队归属变更统一使用迁移接口。
- 验收标准：owner/admin 合法更新成功；member 403；重名 409 且数据不变。

### PRJ-F04 删除项目
- 用户故事：作为 owner，我希望删除不再使用的项目。
- 规则：成员和关联资产删除需事务一致，失败整体回滚；成功 data=null。
- 验收标准：删除后详情 404、资产不可访问；非 owner 403；当前选择清空。

### PRJ-F05 项目资源隔离
- 用户故事：作为用户，我希望项目资产严格隔离。
- 前置条件：项目请求携带 Token 和 X-Project-Id。
- 主流程：认证 -> 建立 ProjectContext -> 按 Resource/Action 校验权限 -> Repository 按 project_id 查询/变更。
- 规则：不能仅凭资源 ID 跨项目访问；无权优先 404。
- 验收标准：A 用户访问 B 资源 404/权限错误；缺项目头 422；缺 Token 401。

### PRJ-F06 项目与团队绑定
- 用户故事：作为团队管理者，我希望项目明确归属于一个团队并继承团队成员关系。
- 主流程：创建项目时必须提交 `team_id` -> 校验团队管理权限 -> 保存归属；没有团队时先创建团队或接受邀请，不再隐式创建团队。
- 规则：`team_id` 必填且仅能指向当前用户可管理的团队；项目列表支持按 `team_id` 筛选；同一项目同一时刻只归属一个团队。
- 验收标准：owner/admin 可在本团队创建；member 创建被拒绝；绑定后团队成员按统一权限访问；跨团队数据不串联。

### PRJ-F07 项目跨团队迁移
- 用户故事：作为项目 owner，我希望将项目迁移到自己拥有的另一团队。
- 前置条件：操作者具备源项目 owner 权限，且是目标团队 owner。
- 主流程：提交目标 team_id -> 校验源项目和目标团队权限 -> 更新归属；权限立即改由目标团队的 TeamMember 关系决定。
- 规则：迁移必须使用专用接口；目标团队不存在或不可访问时不改变数据；操作事务失败整体回滚。
- 验收标准：迁移成功后旧团队成员失去访问，目标团队成员获得对应访问；源项目 admin/member 或仅为目标团队 admin 均 403；失败时项目归属保持原状。

## 7. 非功能要求
后端强制鉴权；跨项目错误不泄露存在性；成员、权限和迁移操作保持事务一致；删除事务可回滚；错误码稳定可断言。

## 8. 当前实现与待确认项
已实现：全局项目名唯一、强制团队归属、按团队筛选、统一 ProjectContext/Resource/Action 鉴权、X-Project-Id 隔离、TeamMember 唯一授权和项目跨团队迁移。
当前限制：项目不能脱离团队存在；项目页不再提供成员入口，成员管理统一在团队页通过 TeamMember 接口完成；旧 ProjectMember 表在校验迁移完成后永久删除，不保留兼容 API 或归档数据。
待确认：项目删除恢复、报告/流量/性能结果保留期限。
