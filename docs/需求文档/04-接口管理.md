## 2. 背景与目标
接口资产描述被测 API 请求模板，不绑定环境；执行器结合环境变量生成实际请求。

## 3. 范围
本期包含接口 CRUD、Header/Query/JSON Body、变量模板和单层分类；不包含 OpenAPI 导入、搜索、试运行和多级分类。

## 4. 角色与权限
项目成员均可维护当前项目接口和分类；管理请求要求 Token、X-Project-Id 和成员关系。

## 6. 功能需求
### API-F01 创建接口定义
- 用户故事：作为成员，我希望保存可复用请求模板。
- 前置条件：name、method、url 合法且字段可 JSON 序列化。
- 主流程：填写 -> 校验项目 -> 保存 -> 返回详情。
- 交互规则：Headers 和 Params 使用扁平的逐行 Key/Value 编辑，可添加和删除行；操作列不显示列标题；GET、DELETE 默认打开 Params，POST、PUT、PATCH 默认打开 Body。
- 请求规则：Params 与 Body 可以同时配置；Headers 名称按大小写不敏感校验重复，Params 名称当前不允许重复。
- Body 规则：可选择 none 或 JSON；本期 JSON 仅支持对象，不支持数组、form-data、文件和纯文本。GET、DELETE 配置 Body 时提示兼容性风险，但不阻止保存。
- 验收标准：合法请求 201 且字段一致；项目头缺失 422；无权项目 404。

### API-F02 查看列表和详情
- 用户故事：作为成员，我希望按分类浏览接口。
- 业务规则：按项目隔离；未分类接口进入默认分组。
- 验收标准：跨项目详情 404；列表不泄露其他项目。

### API-F03 更新接口定义
- 用户故事：作为维护者，我希望修正路径、参数或请求体。
- 业务规则：更新后后续执行立即使用新值。
- 回填规则：已有 Headers、Params 字典转换为逐行编辑数据；已有 Body 按 JSON 模式回填，没有 Body 时显示 none。
- 验收标准：合法更新返回最新值；字段非法 422；跨项目 ID 404。

### API-F04 删除接口定义
- 用户故事：作为维护者，我希望清理过期接口。
- 业务规则：删除 data=null；历史报告保留；孤立用例引用在执行时失败。
- 验收标准：删除后查询 404，其他项目同 ID 不受影响。

### API-F05 管理接口分类
- 用户故事：作为成员，我希望批量重命名或清空分类。
- 业务规则：重命名返回 affected，只影响当前项目；清空只置空 category；不存在分类 affected=0；分类路由优先于整数 ID 路由。
- 验收标准：不改变其他项目；接口仍可查询。

### API-F06 渲染接口请求模板
- 用户故事：作为执行器，我希望发请求前替换环境变量。
- 主流程：加载环境 -> 合并变量 -> 递归渲染 URL/Header/Query/Body -> 发起请求。
- 业务规则：缺失变量形成“变量未找到”失败；不修改原始模板。
- 验收标准：嵌套对象和数组字符串可替换。

## 7. 非功能要求
后端和 Repository 双重项目隔离；敏感模板值在日志和报告中脱敏；错误码稳定。

## 8. 当前实现与待确认项

待确认：HTTP 方法枚举、URL 校验、版本、标签、搜索和批量导入。
