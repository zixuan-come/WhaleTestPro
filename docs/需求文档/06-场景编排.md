# 场景编排

> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

## 1. 文档信息
| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |
| 目标用户 | 项目成员、链路测试人员 |
| 关联模块 | 测试用例、环境、场景报告 |

## 2. 背景与目标
场景将多个测试用例按业务顺序组织为接口链路，通过共享变量验证跨接口流程，并生成一份场景级报告和逐步骤证据。

## 3. 范围
本期包含场景 CRUD、从用例库复制步骤、步骤独立编辑/移除/重排、环境选择、变量传递、执行和报告查看；不包含分支、循环、并发和失败即停止。

## 4. 角色与权限
项目成员可维护和执行当前项目场景；项目外场景和用例不可见。

## 6. 功能需求
### SCN-F01 创建场景
- 用户故事：作为成员，我希望建立业务场景。
- 前置条件：name 非空且不超过 100 字符。
- 主流程：填写 -> 校验项目 -> 创建 -> 返回详情。
- 规则：有序 `steps` 保存每次添加时的独立配置；`case_ids` 保留为来源用例 ID 的兼容投影，不建数据库外键。
- 验收标准：合法创建 201；空场景可保存；无权项目 404。

### SCN-F02 编辑场景基本信息
- 用户故事：作为维护者，我希望更新名称和描述。
- 规则：描述可空，最大 500 字符；更新不改变步骤顺序。
- 验收标准：合法更新成功；非法字段 422。

### SCN-F03 编排用例步骤
- 用户故事：作为链路测试人员，我希望添加和移除步骤。
- 布局：左侧为可搜索的场景导航，右侧展示当前场景的有序步骤。用例库通过“从用例库添加步骤”弹窗打开，支持搜索用例/接口/路径、接口筛选、分页及按勾选顺序批量添加；翻页和筛选保留已选项，同一用例可再次添加为新的独立步骤。
- 步骤列表直接展示名称、请求方法/路径及期望状态；点击“编辑”或双击打开独立编辑窗口。重新应用模板位于该窗口内，确认后载入最新模板草稿，点击应用才更新当前步骤；取消不改变场景。删除场景收纳到顶部“更多”菜单。
- 规则：从当前项目用例复制有效请求配置、名称、状态码、断言和提取规则；每次添加生成独立 `step_id`。步骤可以修改请求方法、路径、Path/Query/Headers/Body、期望状态及高级配置，只影响当前步骤。应用编辑后保存场景才持久化。
- 来源用例或接口后续编辑/删除不覆盖已保存步骤；新步骤保存时验证来源和接口的项目归属。重新应用模板会读取来源最新配置，经确认后只覆盖当前步骤并保留 `step_id`；来源不可访问时保留当前步骤并提示。
- 旧场景中原本缺失或跨项目的引用保留为失效步骤，明确报错，不静默跳过。新旧步骤、重复来源和顺序均通过 `021_scenario_step_snapshots` 保留。
- 验收标准：同一查询用例可添加两次，分别保存 200/404、不同参数或断言；重开及运行保持配置，用例库不变。

### SCN-F04 调整步骤顺序
- 用户故事：作为维护者，我希望拖拽调整业务顺序。
- 规则：执行严格使用持久化顺序。
- 验收标准：重排后请求顺序与页面顺序一致。

### SCN-F05 配置场景变量传递
- 用户故事：作为维护者，我希望前一步提取值供后续请求使用。
- 规则：提取结果加入共享上下文，支持请求字段和断言；敏感值遮罩。
- 验收标准：后续步骤能读取前一步提取值。

### SCN-F06 执行场景
- 用户故事：作为成员，我希望选择环境执行完整链路。
- 流程：选择环境 -> 保存当前修改 -> 初始化上下文 -> 按 steps 快照执行 -> 记录步骤 -> 保存报告。运行前有未保存修改时询问保存，保存失败不能继续运行旧版本。
- 规则：某一步失败后继续；所有步骤通过才算场景通过；空场景生成 0 步报告。
- 验收标准：一次执行只创建一份场景报告；缺失资源步骤失败并记录原因。

### SCN-F07 查看场景报告
- 用户故事：作为排障人员，我希望逐步查看证据。
- 规则：按 sequence 升序展示请求、响应、断言、提取、错误和耗时；响应体最多 64 KiB。
- 验收标准：步骤数量与执行步骤数一致；敏感值不明文展示。

### SCN-F08 单步调试与提取验证
- 步骤行提供“调试”入口，编辑窗口可发送当前草稿，使用场景顶部环境；无需先保存，也不会自动执行前置步骤。无环境、缺失变量或无权来源不能发送请求。
- 展示真实 HTTP 状态、耗时、脱敏 JSON/文本、响应头和实际请求；状态码/断言失败仍保留收到的响应。发送后定位响应区域，支持复制响应。
- 响应为不超过 256 KiB 的 JSON 时，可修改 JSONPath 并点“验证提取”，使用已缓存响应，不重发业务请求；修改请求配置后须重新发送，才可验证提取。
- 提取配置使用“变量名 / 提取表达式 / 提取结果”表格，支持增删行。结果只匹配当前名称与表达式，请求修改后不显示旧验证结果；临时调试变量和报告中的提取变量使用只读表格。
- 提取结果保留原类型，成功后供当前场景后续单步调试复用。敏感结果只展示遮罩，服务端使用原值；规则验证失败不部分写入变量，修正规则可重新验证。缺失变量可以手工填入后发送。
- 临时会话按用户、项目、场景、环境及主/影子库隔离，闲置 10 分钟过期；切换上下文或刷新页面后清除客户端引用。服务端每个会话最多缓存 8 次 JSON 响应、合计约 1 MiB，临时变量最多 100 项/128 KiB。
- 调试不修改场景、用例或接口配置，不生成正式测试报告；步骤配置仍需“应用到当前步骤”后保存场景。单步 HTTP 会实际调用测试目标，SQL、数据集和重试仍不执行。
- 业务断言通过表格配置，显示执行过的对应规则的实际值与结果；修改断言后旧行结果失效，期望状态码或断言改动会提示重新发送更新校验结果。
- 接口：`POST /scenarios/{scenario_id}/debug?env_id=...` 与 `POST /scenarios/{scenario_id}/debug/extract?env_id=...`，均检查当前项目的场景执行权限。

## 7. 非功能要求
报告写入一致；孤立引用可诊断；跨项目访问按 404 处理。

## 8. 当前实现与待确认项
已实现：步骤独立快照和编辑、来源模板重新应用、有序执行、共享上下文、场景报告；压测导入采用保存后的步骤配置及 Path 参数，不重新读取用例库覆盖配置。
当前限制：复用链路执行，不执行 SQL、数据集和重试；数据库不校验 case_ids。
待确认：分支/循环模型、失败策略、节点级超时。
