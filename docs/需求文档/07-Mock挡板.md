> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |

| 关联模块 | 项目、HTTP 路由、Mock 管理 |

## 2. 背景与目标
Mock 在下游不可用或需要稳定异常响应时，按项目返回固定 HTTP 响应；管理接口受权限保护，命中地址公开。

## 3. 范围
本期包含规则 CRUD、Path/Method 精确匹配、延迟、状态码、JSON Body 和命中验证；不包含正则、条件匹配、动态模板和访问审计。

## 4. 角色与权限
管理规则：项目成员可操作，要求 Token + X-Project-Id。命中地址无需登录，project_id 位于 URL。

## 6. 功能需求
### MOCK-F01 创建 Mock 规则
- 用户故事：作为成员，我希望配置固定响应。
- 前置条件：name、path、method 合法；status 为状态码；delay_ms 非负。
- 主流程：填写 -> 校验项目 -> 保存 -> 返回详情和 URL。
- 验收标准：合法请求 201；字段错误 422；非成员 404。

### MOCK-F02 查看/更新/删除规则
- 用户故事：作为成员，我希望维护现有规则。
- 规则：列表和详情按项目隔离；删除不影响其他项目同 ID。
- 验收标准：更新立即生效；删除 200，原命中地址 404。

### MOCK-F03 Path/Method 匹配
- 用户故事：作为被测系统，我希望只有精确规则被命中。
- 规则：project_id、完整 path、HTTP method 同时相同；支持 GET、POST、PUT、DELETE、PATCH。
- 验收标准：相同路径不同方法不能命中；未匹配返回 404。

### MOCK-F04 配置延迟和状态码
- 用户故事：作为测试人员，我希望模拟慢响应和异常状态。
- 规则：delay_ms=0 立即返回，否则先延迟。
- 验收标准：响应状态码等于配置值，耗时接近配置延迟。

### MOCK-F05 返回原始响应
- 用户故事：作为被测系统，我希望获得真实下游格式。
- 规则：body 原样返回，不包装 code/message/data；null 返回 JSON null。
- 验收标准：自定义状态码和 JSON 字段完整保留。

### MOCK-F06 Mock 命中验证
- 用户故事：作为成员，我希望从页面复制 URL 验证规则。
- 规则：命中 URL 为 /mock/{project_id}/{full_path}；命中不校验调用者成员关系。
- 验收标准：复制 URL 可直接请求；删除或不匹配返回 404。

## 7. 非功能要求
管理接口错误稳定；公开端点不泄露管理数据；延迟实现不应阻塞大规模流量。

## 8. 当前实现与待确认项
已实现：精确 Path/Method、延迟、原始 JSON、公开 URL。
待确认：规则优先级、限流、动态响应、文本/二进制 Body。
