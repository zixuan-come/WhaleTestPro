# 回归测试

> 2026-10-18 用户确认后更新：选择测试内容 → 确认执行清单 → 开始回归 → 查看结果。

## 1. 目标与范围

代码更新后，重新执行已有测试，检查原有功能是否正常。测试套件负责整理场景与用例，回归测试负责选择这些内容执行一次并保存结果。

本期包含套件/用例选择、只读预览、环境选择、结果摘要、完整报告入口及可选飞书通知；不包含版本管理、审批、异步任务、实时进度、取消和自动重试。

## 2. 权限

沿用当前项目权限：列表与预览、执行均要求登录并授权当前项目；所选套件、场景、用例、接口、环境按项目隔离。不存在或跨项目的选择返回 404，执行前不产生报告或下游请求。

## 3. 用户操作

### REG-F01 选择测试内容

- 默认“选择测试套件”，也可切换“手动选择用例”；首次不自动勾选任何内容。
- 套件列表展示名称与简介；用例列表展示名称、所属接口和已有标签。
- 支持名称搜索、勾选、“全选当前结果”和清空；筛选变化保留已经勾选的内容，切换选择方式清空原选择。
- 手动模式的标签筛选默认折叠，直接选择已有标签；它只改变候选列表，实际执行范围以勾选清单为准。
- 无套件或用例时展示对应创建入口；尚未选择时不能开始执行。

### REG-F02 确认执行清单

- 展示已选套件、场景、独立用例及场景有序步骤；明确套件数、场景数、步骤数和独立用例数。
- 套件预览采用与执行一致的规则：场景优先，场景内用例不再重复作为独立项运行，直接选择和标签匹配的独立用例去重。
- 多个套件分别执行，不做跨套件去重或共享变量。手动用例互相独立；需要传参的流程使用场景。
- 环境、用例或套件选择变化后使旧预览立即失效，重新读取清单；迟到的旧项目/旧选择响应不得恢复旧数据。
- 空套件、空场景、已删除引用或相对 URL 未选择环境时显示原因并禁用执行。
- 预览只读，不调用被测接口、不生成报告，也不发送通知。

### REG-F03 开始回归

- 只执行当前勾选内容，不因标签为空而自动运行全部用例。
- 开始时重新校验清单所涉及的套件、场景、用例、接口及环境配置摘要；变化返回 409，刷新预览后由用户再次点击开始。
- 套件复用原执行器，保留场景步骤顺序和提取变量传递；手动用例复用单用例执行器，保留数据驱动、断言、重试、SQL 等行为。
- 执行过程中锁定配置并防止重复点击，显示等待提示；切换项目后不展示旧执行迟到的结果。
- 同步执行连接最长等待 10 分钟；网络中断不表示服务端已取消，页面提示先检查回归报告，避免重复执行。

### REG-F04 查看结果和完整报告

- 完成后自动定位结果区，突出通过/失败数量；失败项排在前面。
- 展示场景/用例实际名称、所属套件、状态码差异、执行错误或断言失败说明。
- 通过率、接口覆盖率收进“更多统计”。执行项按场景或独立用例统计；数据驱动/重试仍归入对应独立用例。接口覆盖率为关联到的去重接口数 / 当前项目接口总数。
- 本次回归生成一条根汇总报告；套件、场景、用例通过显式父 ID 归入其下，不重复出现在独立报告列表。
- “查看完整报告”跳转到报告页的回归分类，并直接打开本次报告，即使报告不在当前列表第一页；切换项目或分类时清除该定位。

### REG-F05 通知

- 飞书通知按项目配置：在项目管理列表点击“通知设置”，由所属团队 owner/admin 保存 Webhook 和可选签名密钥，启用后可发送测试通知；普通成员只能读取配置状态并使用通知。
- 回归页“通知设置”显示未配置、已停用、读取失败或已配置；仅已配置并启用时允许勾选，每次回归默认不发送。管理员可直接跳到对应项目配置，成员显示联系管理员。
- 新旧回归入口及按标签定时回归均使用所属项目配置，不回退到部署环境的 FEISHU_WEBHOOK。缺配置、停用或发送失败时返回明确通知提示，保留实际结论和报告。
- 凭据加密保存，不在 GET 响应中回显；留空保留原值，明确勾选清除才删除。测试通知仅使用已保存配置，保存不会自动发送。

## 4. 接口与兼容

- 新增 GET `/regression/options`：当前项目候选套件与用例元数据。
- 新增 POST `/regression/preview`：JSON `mode`（suite/case）、非空 `ids`、可选 `env_id`；返回清单、计数、阻塞原因及 `preview_key`。
- 新增 POST `/regression/run`：上述字段加 `preview_key` 和可选 `notify`，返回结果与字符串 `report_id`。
- 旧 POST `/regression` 保持参数、执行返回结构及定时任务调用兼容。旧接口支持默认全量或标签回归，新页面不再使用空标签作为执行范围。
- 回归报告复用已有模型和关联；项目通知新增 016_project_notification 迁移，仅创建空配置表，不回填全局地址或更改已有业务数据。
- 新增 GET/PUT `/projects/{project_id}/notifications` 和 POST `/projects/{project_id}/notifications/test`；读取须项目成员权限，保存/测试须 project.manage。

## 5. 验收重点

- 非空选择、预览有效及当前项目授权同时满足才允许开始。
- 套件预览清单与实际执行一致，场景变量能传到后续步骤。
- 选择内容变更后无下游调用，直到用户确认新的预览并再次开始。
- 一次回归只有一条根报告；完整报告包含实际执行归属与证据。
- 跨项目选择、迟到响应、重复点击、空套件、已删除引用、失败说明和完整报告定位均可验证。
