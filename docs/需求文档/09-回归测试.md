# 回归测试

> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |
| 目标用户 | 项目成员、测试负责人 |
| 关联模块 | 用例执行、报告、Prometheus、飞书通知 |

## 2. 背景与目标
回归测试批量执行当前项目用例，汇总通过率和接口覆盖率，可将摘要发送到飞书，也是定时调度的执行内核。

## 3. 范围
本期包含用例集合、标签筛选、环境选择、同步执行、统计、指标和通知；不包含独立回归任务实体、历史、取消、并发和失败重跑。

## 4. 角色与权限
项目成员可触发当前项目回归；用例和接口均按项目隔离。

## 6. 功能需求
### REG-F01 创建回归任务
- 用户故事：作为成员，我希望发起一次回归。
- 前置条件：Token 和 X-Project-Id 有效。
- 主流程：选择环境、范围、通知 -> 提交 -> 加载当前项目数据 -> 执行汇总。
- 验收标准：无权限请求返回 401/422/404；不执行跨项目数据。

### REG-F02 配置用例集合
- 用户故事：作为负责人，我希望指定部分用例或默认全部。
- 规则：case_ids 为空加载当前项目全部用例；输入顺序作为结果顺序。
- 验收标准：指定两个用例 total=2；资源异常记失败但继续。

### REG-F03 按标签筛选
- 用户故事：作为负责人，我希望只回归带指定标签的用例。
- 规则：仅 case_ids 为空时按 tag 筛选；同时传两者时 tag 不筛选。
- 验收标准：不含标签的用例不得执行。

### REG-F04 触发回归执行
- 用户故事：作为成员，我希望一次请求完成整组回归。
- 主流程：逐个复用单用例执行 -> 记录异常 -> 继续 -> 返回汇总。
- 规则：应用数据集、重试、SQL、断言并生成用例报告。
- 验收标准：单个异常不阻断整体；每个实际用例有报告。

### REG-F05 查看回归结果
- 用户故事：作为负责人，我希望看到总数、通过数、失败数和覆盖率。
- 规则：passed=passed_count==total；pass_rate=passed_count/total，空集为 0；接口覆盖率=被用例关联接口数/项目接口总数，分母 0 为 0。
- 验收标准：统计基于项目全量资产，结果含逐用例明细。

### REG-F06 发送回归通知
- 用户故事：作为负责人，我希望把摘要发到飞书。
- 规则：notify=true 且有 Webhook 才发送；至少包含通过数、总数、通过率、接口覆盖率。
- 验收标准：notify=false 或无 Webhook 不发送；通知失败不改变回归结果。

## 7. 非功能要求
单用例异常隔离；指标写入 Prometheus Gauge；错误码稳定可断言。

## 8. 当前实现与待确认项
已实现：按用例/标签执行、通过率、接口覆盖率、飞书通知、前端汇总。
当前限制：同步请求可能超时；无取消和历史实体；空回归 passed=true 但 total=0。
待确认：异步回归、并发度、保留策略和通知渠道。
