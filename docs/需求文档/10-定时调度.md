# 定时调度

> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

## 1. 文档信息
| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |
| 目标用户 | 项目成员、测试负责人 |
| 关联模块 | 回归、Celery Beat、RedBeat、Redis |

## 2. 背景与目标
通过标准五段 Cron 周期性触发当前项目回归。定义保存于 MySQL，运行条目同步到 RedBeat/Redis，由 Celery Beat 派发 Worker。

## 3. 范围
本期包含任务 CRUD、Cron 校验、启停、RedBeat 同步、按标签回归和默认通知；不包含时区、执行历史、指定 case_ids、场景调度和独立手工触发。

## 4. 角色与权限
项目成员可维护当前项目任务；请求必须 Token、X-Project-Id 和成员关系。

## 6. 功能需求
### SCHED-F01 创建定时任务
- 用户故事：作为成员，我希望保存周期性回归定义。
- 前置条件：name 和五段 Cron 合法。
- 主流程：填写 -> 校验 -> 保存 MySQL -> 同步 RedBeat。
- 验收标准：启用任务 201 且有唯一调度条目；非法字段 422。

### SCHED-F02 配置 Cron
- 用户故事：作为维护者，我希望按标准 Cron 控制周期。
- 规则：必须五段并能被 Celery crontab 解析；使用部署环境时区。
- 验收标准：非法表达式不写入；更新后使用新表达式。

### SCHED-F03 启用/停用任务
- 用户故事：作为维护者，我希望暂停任务而不删除定义。
- 规则：停用删除 RedBeat 条目但保留 MySQL；启用重新同步。
- 验收标准：停用期间不触发，定义仍可查。

### SCHED-F04 更新任务
- 用户故事：作为维护者，我希望修改 Cron、标签和名称。
- 规则：最新 Cron、project_id、tag 覆盖 RedBeat；条目名称由 ID 唯一确定。
- 验收标准：更新后不串项目和标签；不存在任务 404。

### SCHED-F05 删除任务
- 用户故事：作为维护者，我希望删除不再需要的调度。
- 规则：同时删除 MySQL 和 RedBeat；RedBeat 缺失时忽略 KeyError。
- 验收标准：两处均不存在且 API 成功。

### SCHED-F06 手动触发任务
- 用户故事：作为负责人，我希望立即验证配置。
- 当前状态：当前版本没有独立入口，属于待规划，不进入本期验收。

### SCHED-F07 查看执行结果
- 用户故事：作为负责人，我希望查看定时执行是否成功。
- 当前状态：无独立调度历史，结果通过回归报告和通知查看。

## 7. 非功能要求
Worker 无论成功失败都关闭数据库 Session；跨项目任务不得执行；同步失败可诊断。

## 8. 当前实现与待确认项
已实现：MySQL 定义、RedBeat 同步、启停、按 tag 回归、默认通知。
待规划：手动触发、执行历史、时区和失败告警。
