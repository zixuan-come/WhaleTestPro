# 性能测试

> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

## 1. 文档信息
| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |
| 目标用户 | 项目成员、性能测试人员 |
| 关联模块 | Locust、Celery、Redis、Prometheus/Grafana |

## 2. 背景与目标
创建并异步执行 Locust 压测任务，采集 RPS、平均响应时间和失败率，并提供实时观察入口。

## 3. 范围
本期包含任务 CRUD、参数校验、异步启动、Locust 调度、指标采集、最终结果保存和前端轮询；不包含停止/取消、P95/P99 历史、多请求模型和并发任务。

## 4. 角色与权限
项目成员可操作当前项目任务；Worker 必须按 project_id 再次查询。

## 6. 功能需求
### PERF-F01 创建性能任务
- 用户故事：作为性能测试人员，我希望保存压测配置。
- 前置条件：name、target_host、target_path 合法；users、spawn_rate、duration 为正整数。
- 验收标准：合法创建 201、初始 pending；参数小于 1 返回 422。

### PERF-F02 配置 Locust 参数
- 用户故事：作为性能测试人员，我希望控制并发、启动速率和持续时间。
- 规则：host/path 可从接口和环境选择或手工输入；当前脚本只对 path 发 GET。
- 验收标准：参数准确传入 Locust /swarm。

### PERF-F03 查看任务详情和状态
- 用户故事：作为用户，我希望轮询看到状态和最新指标。
- 规则：状态为 pending/running/done；运行中展示 RPS、平均耗时和失败率。
- 验收标准：跨项目 ID 404；running 可观察。

### PERF-F04 触发性能任务
- 用户故事：作为用户，我希望异步启动且不阻塞页面。
- 流程：API 标记 running -> Celery 派发 -> Worker 查询任务 -> 调用 Locust Master。
- 验收标准：API 立即返回 running；Worker 不执行其他项目任务。

### PERF-F05 查看性能结果
- 用户故事：作为负责人，我希望看到最终指标。
- 规则：每 2 秒采集；duration 到达后停止 Locust，保存最后采样并标记 done。
- 验收标准：结束状态 done；实时 Gauge 清零。

### PERF-F06 Prometheus 指标关联
- 用户故事：作为运维人员，我希望观察实时指标。
- 规则：采集 RPS、用户数、失败率和平均耗时；结束清零。
- 验收标准：/metrics 可解析且运行中变化。

### PERF-F07 影子库写入隔离
- 用户故事：作为测试人员，我希望写操作不污染主库。
- 规则：平台提供 X-Shadow 机制，外部系统配合不由平台保证。
- 验收标准：平台 SQLAlchemy Session 的 shadow 操作路由影子库。

## 7. 非功能要求
异步异常可诊断；running 时运行按钮禁用；共享 Master/Redis 时提示并发限制。

## 8. 当前实现与待确认项
已实现：Locust GET、Celery、Redis target_path、Prometheus、Grafana/Locust 入口。
当前限制：异常不统一回滚 failed；共享 Redis key/Master 不适合并发任务。
待确认：取消接口、失败状态、请求模型、历史指标保留。
