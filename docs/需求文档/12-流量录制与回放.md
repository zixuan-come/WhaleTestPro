# 流量录制与回放

2026-10-18，按当前实现更新。

## 普通用户操作

1. 选择项目，打开「流量回放」，点击「开始录制」。
2. 前往「接口测试」，打开接口的「接口调试」，选择环境并发送请求。
3. 回到「流量回放」，查看「我的最近录制」，点击「停止录制」。
4. 点击记录的「详情」查看已解析的 Path、Query、Headers、Body 和响应。
5. 点击「回放」，显式选择当前项目的目标环境。替换 *** 脱敏值，Headers/Query/Body 可引用该环境变量，例如 `Bearer ${token}`。
6. 点击「发送回放」，对比状态码和响应体。额外忽略字段用逗号分隔，如 `trace_id, request_id`。配置仅影响本次发送，不修改原接口或录制记录。

## 范围与隔离

- 录制开关按用户、项目保存，切换页面后保留；有效期一小时，上限1000条。不同成员不会互相开启、停止录制。最近一次列表按 capture_id 查询；项目成员可通过「项目全部记录」查看当前项目共享记录及历史入站记录。
- 当前录制源为平台内的接口调试，记录解析环境变量和 Path 参数后的请求及实际返回的响应。包含收到 HTTP 4xx/5xx 的请求；没有收到响应的网络失败不生成可回放记录。
- 不自动捕获其他浏览器页面访问 WhaleShop 的流量，不录制压测、套件或场景执行产生的请求。不提供代理或浏览器插件。
- 请求及响应按结构化字段脱敏，跨字段回显的已知凭证一并脱敏。请求/响应合计超过64KB或截断时跳过并提示。停止、过期或重新开始后才完成的旧请求不加入记录。
- 录制保存失败不影响接口原执行结果，调试区显示录制警告。
- 调试录制同步保存到数据库，不依赖 Celery 队列；保留旧入站中间件与异步消费能力，旧行不清除、不转换。管理/认证历史入站数据继续隐藏；新调试记录允许业务系统使用 `/auth/...` 等路径，与平台入站记录区分。

## 回放

- 新调试记录必须选择当前项目环境，不默认发送到本机。旧 API 仍兼容省略环境的本机示例订单回放；页面始终要求选择环境。
- 按目标环境 Base URL 加相对路径发送，保留录制 Query、普通请求头、JSON Body；允许用户在本次配置中替换 Headers、Query 或整个 Body（null表示清空）。环境变量未解析、存在 ***、路径无效时拒绝发送。
- 不转发 Host、Content-Length、Connection 等传输头；Header 替换不区分大小写。禁止自动重定向，避免携带凭证改变目标。
- 回放是一次真实请求，写入操作可能修改目标环境数据。外部系统仅接收 X-Shadow 提示，是否隔离由被测系统实现；不会转发平台内部影子签名。
- 内部影子凭证仍只允许 `/demo/orders`，绑定方法和路径，短期有效。平台管理接口不能使用内部影子回放。
- 状态码变化必定判为差异。响应体默认 id比较整数类型、created_at/updated_at比较字符串类型、token忽略；额外忽略规则覆盖默认值。其他字段逐字段比较。响应超过64KB明确判为未完整比较，不误报一致。结果中的敏感字段脱敏。
- 本期支持接口调试现有的JSON请求配置；不支持文件/二进制上传、自动登录和关联变量链路回放。

## API与迁移

- GET `/traffic/capture`，POST `/traffic/capture/start`、`/stop`：认证项目上下文提供用户，不允许提交他人ID；项目成员可录制和回放。
- GET `/traffic/records?limit=21&offset=0&capture_id=...`：每次最多100条，稳定按录制时间、ID倒序；详情和回放仍按项目授权。
- POST `/traffic/replay/{id}`：env_id、headers、params、body、field_rules。不存在记录404；无效配置400。
- 017增量迁移新增 traffic_capture 表以及录制来源、批次、接口名称、Query、目标主机和耗时等可空字段；可重复执行，保留历史行。项目删除同步删除录制开关。

后端专项覆盖开关归属、有效期、停止/重开竞态、请求快照、脱敏、大小限制、环境校验、Header覆盖、变量、状态码差异、网络错误和迁移幂等。前端专项覆盖显式发送、参数校验、重复提交、切项目后迟到响应、分页和错误保留。隔离端到端使用合成服务，不对WhaleShop或用户业务库发请求。具体结果见本次交付记录。
