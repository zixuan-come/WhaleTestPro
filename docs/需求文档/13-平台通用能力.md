## 2. 背景与目标
横切能力提供统一响应、异常、认证与项目上下文、熔断、指标、健康检查和前端工作台规范，保证各模块行为一致。

## 3. 范围
本期包含统一响应、全局异常、项目隔离、熔断、可观测性、导航主题和健康端点；不包含统一审计、Trace、生产级安全审计、多实例共享熔断和独立移动端。

## 4. 角色与权限
普通业务接口要求 Bearer Token；项目内资源还要求 X-Project-Id 和成员关系；无权资源优先返回 404。

## 6. 功能需求
### PLAT-F01 统一 API 响应
- 用户故事：作为 API 使用者，我希望不同业务接口格式一致。
- 规则：成功为 code/message/data 且 code=0；失败 Body code 与 HTTP 一致；创建通常 201，删除 200 且 data=null；Mock、Prometheus、Swagger、静态和流式协议例外。
- 验收标准：普通业务成功/失败均符合信封，特殊协议保持原协议。

### PLAT-F02 全局异常处理
- 用户故事：作为用户，我希望参数错误和服务异常可读、可断言。
- 规则：HTTPException、Pydantic 校验错误和未处理异常统一包装，不泄露堆栈。
- 验收标准：校验错误 422；未处理异常不返回 HTML、不致进程退出。

### PLAT-F03 认证与项目上下文
- 用户故事：作为业务模块，我希望统一获得当前用户和项目。
- 流程：认证 Token -> 读取 X-Project-Id -> 查询成员 -> 注入上下文。
- 规则：Repository 继续按 project_id 过滤；跨项目优先 404。
- 验收标准：缺 Token 401；缺项目头 422；非成员 404；切换项目后请求头更新。

### PLAT-F04 熔断和容错
- 用户故事：作为执行器，我希望下游连续故障时快速失败。
- 规则：每个接口 ID 独立内存熔断；连续 5 次连接异常或 5xx 后 open；open 10 秒 half-open；成功 1 次 closed；2xx/3xx/4xx 不计失败。
- 验收标准：达到阈值后快速失败；10 秒后可试探；4xx 不触发累计。

### PLAT-F05 可观测性与指标
- 用户故事：作为运维人员，我希望通过 Prometheus/Grafana 观察平台。
- 规则：采集 FastAPI 基础、回归通过率/覆盖率和压测实时指标；/metrics 使用文本协议。
- 验收标准：Prometheus 可解析；运行指标变化，结束 Gauge 清零。

### PLAT-F06 前端主题和导航
- 用户故事：作为用户，我希望快速切换模块并保持主题偏好。
- 规则：导航按测试/运维/系统分组；顶部项目切换支持切换、创建、项目管理；亮暗主题持久化；页面具备加载、空数据、错误、重试、提交中和危险确认。
- 验收标准：切换项目触发重载并更新 X-Project-Id；刷新后主题保持；窄屏核心操作可用。

### PLAT-F07 健康检查和公开端点
- 用户故事：作为部署系统，我希望探测应用存活。
- 公开端点：/health 统一 JSON 200；/metrics Prometheus 文本；/docs 和 /openapi.json Swagger；/mock 原始响应；/static 文件协议。
- 验收标准：公开端点不要求 Token；特殊协议不被包装。

## 7. 非功能要求
响应格式稳定；权限后端强制；熔断和指标开销可控；前端错误状态可恢复。

## 8. 当前实现与待确认项
已实现：统一响应、异常处理、项目上下文、内存熔断、Prometheus、主题导航和健康端点。
当前限制：熔断不跨进程；健康检查主要反映应用存活；无审计和 Trace。
待确认：分布式熔断、深度健康检查、审计保留和移动端策略。
