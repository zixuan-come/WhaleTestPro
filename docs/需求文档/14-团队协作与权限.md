## 2. 背景与目标
团队是项目协作和授权的主体。平台通过 owner/admin/member 三种团队角色、普通成员模块写权限以及统一的 Resource/Action 策略，保证成员在多个项目中的权限一致，并避免旧项目成员记录抬高权限。

## 3. 范围
本期包含团队创建与列表、信息维护、成员邀请与处理、成员角色和移除、退出团队、所有权转让、空团队删除、普通成员写权限配置、团队项目成员投影同步和统一项目授权。不包含组织层级、自定义角色、自定义权限键、邀请链接、邮件通知和审计日志。

## 4. 角色与权限
| 操作 | owner | admin | member |
| --- | ---: | ---: | ---: |
| 查看团队、成员、权限 | 允许 | 允许 | 允许 |
| 编辑团队信息 | 允许 | 允许 | 禁止 |
| 搜索、邀请、改角色、移除成员 | 允许 | 允许 | 禁止 |
| 配置普通成员写权限 | 允许 | 允许 | 禁止 |
| 转让所有权、删除团队 | 允许 | 禁止 | 禁止 |
| 退出团队 | 转让后允许 | 允许 | 允许 |
| 读取/执行项目资源 | 允许 | 允许 | 允许 |
| 修改项目资源 | 允许 | 允许 | 按模块开关 |

约束：每个团队恰有一个 owner；成员管理接口不能直接创建或设置 owner；owner 不能被降级、移除或直接退出。

## 6. 功能需求
### TEAM-F01 创建、查看和切换团队
- 用户故事：作为已登录用户，我希望创建团队并在自己加入的团队之间切换。
- 前置条件：名称去除首尾空格后非空且不超过 100 字符，描述可空且不超过 500 字符。
- 主流程：提交团队信息 -> 校验名称唯一 -> 创建团队 -> 创建者成为 owner -> 返回 201；列表只返回当前用户所属团队。
- 验收标准：重名 409；非法字段 422；未登录 401；创建成功后列表中角色为 owner；切换团队时清空旧项目选择。

### TEAM-F02 编辑团队信息
- 用户故事：作为 owner/admin，我希望更新团队名称和简介。
- 规则：仅 owner/admin；名称仍需唯一；普通成员只读。
- 验收标准：owner/admin 更新成功；member 403；重名 409 且原数据不变；非成员 404。

### TEAM-F03 搜索、添加或邀请成员
- 用户故事：作为 owner/admin，我希望搜索已注册用户，并直接添加或邀请其以 admin 或 member 身份加入。
- 前置条件：搜索关键词长度 2 至 50，返回上限 1 至 50；邀请角色只能是 admin/member。
- 主流程：搜索候选 -> 选择用户和角色 -> 直接创建 TeamMember，或创建 pending 邀请并等待被邀请人处理；成功加入后同步团队项目兼容投影。
- 规则：用户不存在 404；已是成员时 409；邀请模式下已有 pending 邀请时 409；不得添加或邀请为 owner。
- 验收标准：owner/admin 可直接添加或邀请；member 403；非法角色或参数 422；邀请记录包含邀请人、被邀请人、角色和状态。

### TEAM-F04 处理团队邀请
- 用户故事：作为被邀请人，我希望接受或拒绝团队邀请。
- 主流程：查看自己的邀请 -> 选择接受或拒绝 -> 更新状态；接受时创建 TeamMember 并同步团队下所有项目的兼容投影。
- 规则：只能处理发给自己的 pending 邀请；已处理邀请不可重复处理；拒绝不创建成员关系。
- 验收标准：接受后团队列表和成员列表可见；拒绝后仍不能访问团队；他人处理或无效邀请 404/409。

### TEAM-F05 查看和管理团队成员
- 用户故事：作为团队成员，我希望查看成员；作为 owner/admin，我希望调整 admin/member 角色或移除成员。
- 规则：所有成员可查看；仅 owner/admin 可管理；owner 不可通过本功能改角色或移除；角色变化与移除须同步团队下全部项目的兼容投影。
- 验收标准：member 管理操作 403；owner 目标 409；跨团队成员 404；合法变更后团队与项目投影一致。

### TEAM-F06 退出团队
- 用户故事：作为 admin/member，我希望主动退出团队。
- 规则：owner 必须先转让所有权；退出后删除 TeamMember，并删除该团队项目中的兼容投影。
- 验收标准：admin/member 退出成功；owner 直接退出 409；退出后团队从列表消失且项目访问被拒绝。

### TEAM-F07 转让团队所有权
- 用户故事：作为 owner，我希望将所有权转让给现有团队成员。
- 主流程：选择非 owner 成员 -> 确认 -> 目标角色变为 owner，原 owner 变为 admin -> 同步项目兼容投影。
- 规则：仅当前 owner；目标必须是同团队现有成员且不能是本人；转让后仍保持唯一 owner。
- 验收标准：admin/member 403；无效目标 404/409；成功后新 owner 可执行 owner 专属操作，原 owner 不可执行。

### TEAM-F08 删除空团队
- 用户故事：作为 owner，我希望删除不再使用且没有项目的团队。
- 规则：仅 owner；团队下存在项目时 409；删除成员、邀请和权限配置须保持事务一致。
- 验收标准：admin/member 403；有项目时团队保持不变；空团队删除后不可查询且当前团队选择清空。

### TEAM-F09 配置普通成员写权限
- 用户故事：作为 owner/admin，我希望按模块控制普通成员能否修改项目资源。
- 规则：当前只支持 role=member；可配置权限键为 interface.write、case.write、environment.write、mock.write、schedule.write、perf.write、scenario.write、suite.write；未开启时 member 仍保留 read/execute，但无对应 write；owner/admin 默认拥有全部权限。
- 验收标准：owner/admin 可查询和开关；member 只读且修改 403；未知角色或权限键 422；开关关闭后对应写请求 403，打开后成功。

### TEAM-F10 统一项目授权与成员同步
- 用户故事：作为平台使用者，我希望所有项目接口采用一致、可解释的权限规则。
- 主流程：Bearer 认证 -> 读取 X-Project-Id -> 构造 ProjectContext -> 按 Resource 和 Action(read/write/execute/manage/owner)授权 -> 执行业务。
- 规则：owner 允许全部动作；admin 除 owner 动作外均允许；member 默认允许 read/execute，write 由 TEAM-F09 控制，不允许 manage/owner；团队项目以 TeamMember 为主权限来源，旧 ProjectMember 只能兼容且不得抬权；无项目访问关系按 404 处理。
- 验收标准：同一角色在各模块结论一致；旧 ProjectMember 高角色不能覆盖低团队角色；非成员不知道项目是否存在；成员变化后所有团队项目的兼容投影同步。

## 7. 接口范围
- /teams：创建、列表。
- /teams/{team_id}：更新、删除；/transfer、/leave：所有权转让和退出。
- /teams/{team_id}/members：成员列表、新增、改角色、移除；/teams/{team_id}/member-candidates：候选搜索。
- /teams/{team_id}/invitations：发起邀请；/teams/invitations 与 /teams/invitations/{invitation_id}/respond：查看和处理本人邀请。
- /teams/{team_id}/permissions：查询和配置普通成员写权限。

## 8. 非功能要求
所有管理操作后端强制鉴权；无权访问不泄露团队或项目存在性；角色、成员、权限和兼容投影更新须保持事务一致；错误码和提示稳定可断言。

## 9. 当前实现与待确认项
已实现：团队 CRUD、邀请处理、角色管理、退出、所有权转让、空团队删除、八项普通成员写权限、统一 ProjectContext/Resource/Action 授权和 ProjectMember 投影同步。
当前限制：只支持内置三角色和固定权限键；邀请对象必须是已注册用户；前端邀请列表仅展示团队 ID。
待确认：邀请撤回/过期、批量邀请、审计日志和自定义角色均不进入当前版本验收。
