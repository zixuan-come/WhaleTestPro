# 测试套件

> PRD v2：按用户功能拆分，供产品确认、Butterfly Agent 评审和测试设计使用。

## 1. 文档信息
| 项目 | 内容 |
| --- | --- |
| 状态 | 评审草案 |
| 目标用户 | 项目成员、测试维护人员、测试执行人员 |
| 关联模块 | 测试用例、场景、环境、报告、定时调度 |

## 2. 背景与目标
测试套件将场景、指定用例和标签匹配用例组合为可复用的执行单元，用于冒烟、回归等测试集合的一键执行和定时执行，并生成统一的套件汇总报告。

## 3. 范围
本期包含套件 CRUD、三种套件类型、场景/用例/标签组合、环境选择、去重执行、汇总结果、报告持久化和定时任务关联。不包含套件嵌套、并行执行、失败即停止、运行中取消、执行历史对比和独立重试策略。

## 6. 功能需求
### SUITE-F01 创建测试套件
- 用户故事：作为测试维护人员，我希望创建可重复使用的测试集合。
- 前置条件：名称去除首尾空格后非空且不超过 100 字符；描述可空且不超过 500 字符；type 为 scenario、case 或 mixed。
- 主流程：填写基本信息和内容 -> 校验项目写权限与字段 -> 保存 -> 返回 201。
- 规则：创建时 scenario_ids、case_ids 各最多 100 个，tags 最多 20 个且标签不能为空白；未填写的集合保存为空。
- 验收标准：合法创建后列表可见；空名称、非法类型、超限集合返回 422；无写权限 403；无项目访问关系 404。

### SUITE-F02 查看套件列表与详情
- 用户故事：作为项目成员，我希望查看当前项目的套件及其组成。
- 主流程：进入页面 -> 分页加载列表 -> 查看名称、类型、描述、场景数、用例数、标签数和创建时间；可按 ID 获取详情。
- 规则：列表 skip 不小于 0，limit 为 1 至 100；只返回 X-Project-Id 对应项目数据。
- 验收标准：成员可读；跨项目同 ID 不可见；不存在返回 404；空列表返回空数组而非异常。

### SUITE-F03 编辑测试套件
- 用户故事：作为维护人员，我希望调整套件信息和内容。
- 规则：采用全量 PUT 更新；名称、描述和类型遵循创建规则；更新不得改变 project_id；需要 suite.write。
- 验收标准：合法更新后重新查询一致；跨项目 404；无写权限 403；字段非法 422 且原数据不变。

### SUITE-F04 删除测试套件
- 用户故事：作为维护人员，我希望删除不再使用的套件。
- 规则：需要 suite.write；只删除当前项目目标；成功 data=null。
- 验收标准：删除后详情 404；跨项目 404；无写权限 403；关联定时任务如何处理按当前数据库约束验证。

### SUITE-F05 组合场景、用例与标签
- 用户故事：作为维护人员，我希望通过显式 ID 和标签组合测试范围。
- 执行顺序：先按 scenario_ids 顺序运行场景，再按 case_ids 顺序运行未执行用例，最后按项目用例顺序运行命中任一 tags 且未执行的用例。
- 规则：一个用例若已在场景或显式用例中执行，标签阶段不重复执行；引用不存在或不属于当前项目的场景/用例时记录失败项，不跨项目执行；type 用于套件分类展示，不单独裁剪已配置集合。
- 验收标准：混合来源按规定顺序执行；同一用例跨来源只执行一次；标签取并集匹配；无匹配项时不凭空增加结果。

### SUITE-F06 选择环境并执行套件
- 用户故事：作为项目成员，我希望选择环境并一键运行套件。
- 主流程：点击运行 -> 选择环境或默认环境 -> 校验 suite.execute -> 依次执行套件内容 -> 返回汇总。
- 规则：env_id 必须属于当前项目；成员默认拥有 execute；空套件允许发起，但结果按失败处理且总数为 0；执行期间某项失败不阻断后续项。
- 验收标准：合法环境执行成功；跨项目/不存在环境拒绝或产生可诊断错误；单项失败后后续仍执行；缺套件 404。

### SUITE-F07 汇总结果并生成报告
- 用户故事：作为执行人员，我希望看到套件整体结果并在报告中追踪。
- 规则：返回 suite_id、suite_name、total、passed、failed、pass_rate、duration_ms、scenario_count、case_count 和明细；total 统计场景结果与独立用例结果；全部结果通过且 total>0 时套件通过；保存 execution_type=suite 的项目报告并关联 suite_id/name。
- 验收标准：total=passed+failed；通过率计算正确；场景和独立用例计数正确；报告项目归属、套件信息和明细与本次执行一致。

### SUITE-F08 定时执行测试套件
- 用户故事：作为维护人员，我希望通过 Cron 周期运行指定套件。
- 主流程：创建/更新定时任务并指定 suite_id -> 调度器同步 -> 到期后以 schedule.project_id 执行套件 -> 保存套件报告。
- 规则：定时任务同时具有 suite_id 和 tag 时优先执行 suite_id；未指定 suite_id 时保持按 tag 回归的兼容逻辑；禁用或删除任务时移除调度条目。
- 验收标准：到期任务只执行所属项目套件；suite_id 优先级正确；禁用后不再触发；执行结果可在报告中查询。

## 7. 接口范围
- POST /suites：创建套件。
- GET /suites、GET /suites/{suite_id}：列表与详情。
- PUT /suites/{suite_id}、DELETE /suites/{suite_id}：更新与删除。
- POST /suites/{suite_id}/run：按可选 env_id 执行并返回汇总。
- 定时任务接口通过 suite_id 关联套件，调度任务执行时传递 project_id、tag、suite_id。

## 8. 非功能要求
套件和引用资源必须按项目隔离；单次执行结果可诊断且报告写入一致；长耗时任务的失败不得留下跨项目数据；业务接口统一使用 ApiResponse 信封，错误码稳定可断言。

## 9. 当前实现与待确认项
已实现：套件 CRUD、场景/用例/标签组合、跨来源用例去重、环境执行、汇总结果、套件报告和定时任务关联。
当前限制：场景和用例引用以 JSON ID 列表保存，不建外键；执行为同步串行；删除套件后的定时任务关联行为需在验收中重点验证；更新模型尚未独立限制 ID/标签集合上限，应按当前接口实测记录。
待确认：套件嵌套、并行度、失败策略、异步任务状态和历史趋势均不进入当前版本验收。
