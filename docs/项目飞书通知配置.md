# 项目飞书通知配置

## 用户操作

1. 在目标飞书群的设置中添加自定义机器人，复制它的 Webhook 地址。
2. 登录 WhaleTestPro，在「项目管理」找到目标项目，点击该行的「通知设置」。只有所属团队所有者和管理员可以配置。
3. 粘贴地址，勾选“启用本项目的飞书通知”。如果机器人启用了签名校验，在“机器人安全设置”中填写签名密钥。若使用关键词校验，请在飞书机器人中允许关键词 `WhaleTestPro`；若使用 IP 白名单，请允许部署服务器的出口 IP。
4. 点击“保存”。保存成功后地址和密钥输入框会清空，显示“已保存，留空保留”；这是正常的凭据保护行为。
5. 点击“发送测试通知”，到群里确认消息。该按钮使用已保存配置；有未保存修改时不可用。保存本身不会发送消息。
6. 回到「回归测试 → 通知设置」，确认状态为“本项目已配置飞书通知”，勾选“执行完成后发送飞书通知”，再开始回归。每次进入页面默认不勾选。

机器人创建、消息格式和签名规则参见[飞书官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。平台支持飞书自定义机器人的 HTTPS `/open-apis/bot/v2/hook/…` 地址。

## 修改和停用

- 更换地址或签名密钥：填写新值后保存，其他留空字段保持不变；更换机器人时注意同步更新或清除原签名密钥。
- 暂停通知：取消“启用本项目的飞书通知”并保存，已保存凭据保留。停用时仍可发送测试消息验证配置。
- 删除地址：勾选“清除已保存的 Webhook 地址”并保存，同时停用通知和清除关联签名密钥。
- 删除签名：展开安全设置，勾选“清除已保存的签名密钥”并保存。
- 普通成员可以看到配置状态并在回归时选择通知，不能读取凭据、修改设置或发送测试通知。

未配置、已停用或读取状态失败时，回归通知复选框禁用；管理员可通过“去配置”跳转到对应项目。通知状态读取失败不会妨碍执行不带通知的回归。

## 发送结果

只有 HTTP 成功且飞书业务码为 0 才视为发送成功。超时、非成功 HTTP 响应、关键词/签名/IP 校验失败均显示明确提示，不回显 Webhook 或飞书原始响应。通知失败不改变回归结论，不丢失测试报告。消息只包含产品名、项目名、通过数量、通过率和接口覆盖率，不包含接口请求凭据。

## 部署与兼容

- 新增 `project_notification` 表及 `016_project_notification` 幂等迁移。升级创建空表，不复制旧全局地址，不修改已有项目和报告数据；主库与影子库均应用迁移。
- 新增运行依赖 `cryptography`；Webhook 和可选签名密钥分别通过 Fernet 加密，密钥按项目 ID 和部署 `SECRET_KEY` 派生。备份和升级须保留 `SECRET_KEY`；轮换后管理员需要重新保存通知凭据。
- 全局环境变量 `FEISHU_WEBHOOK` 保留读取兼容，但新旧回归执行与按标签定时回归均不会向它发送。旧部署需要分别为每个项目配置地址。
- 不改变测试套件和场景执行规则，不新增套件定时通知开关。
- GET `/projects/{project_id}/notifications` 只返回 enabled、configured、signing_configured、can_manage。PUT 同路径保存；POST `/projects/{project_id}/notifications/test` 发送固定测试消息。
- 所有读取按项目成员关系鉴权，保存/测试要求 `project.manage`。外部发送禁止跳转，只接受固定飞书域名和机器人路径，并设置连接/读取超时。
